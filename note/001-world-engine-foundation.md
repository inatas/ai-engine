技术决策（2026-10-12）：用户确认采用全 TypeScript。前端 React + Vite + Ant Design，服务端 Node.js + NestJS，共享 Zod 契约，PostgreSQL + Prisma，pnpm workspace；规则与服务端验证使用 Vitest，浏览器流程使用 Playwright。选择依据是编辑器与服务端共享 schema 和类型、纯计算引擎可独立验证、同语言减少协调成本；不因未来接入模型而引入 Python。

规划 apps/web、apps/server、packages/contracts、packages/engine；核心只依赖共享契约，外部 I/O 与模型适配在 server。依赖与 API 禁用写入 lint，并结合解析目标的包依赖检查、独立编译与 CI；明确覆盖动态导入、别名、间接依赖和全局 API。两类世界存档从第一天带 schemaVersion=1，仅支持当前版本，不兼容旧数据。此前可用 SQLite 的未实施方案直接替换为 PostgreSQL，JSON 数值统一为安全整数。

破坏性影响：后续首次实现即按当前技术与存档格式落地；当前没有程序或存档需要转换，不增加迁移或并存方案。依赖版本与具体鉴权组件仍需在实施前核实锁定。

## 2. 首期目标

目标一：作者在专业剧本编辑器中从空白或模板初始化完整世界，通过引用选择、条件与效果编辑、校验与试玩形成可运行定稿，不需要手写 JSON。

目标二：玩家注册登录后启动本人定稿，运行独立世界，保存、列出、读取并恢复自己的存档。其他账号不能读取或修改这些数据。

贯穿验收的流程为：注册 → 建立草稿 → 领域编辑 → 保存重开 → 校验修正 → 试玩 → 定稿 → 新游戏 → 执行动作 → 保存检查点 → 退出重登 → 读取并恢复 → 继续游戏。

先验证可执行定义与权威状态。首期不接入真实模型，不宣称已完成 AI 自主 NPC 或自然语言游戏体验；固定行为与结构化反馈用于验证后续模型也必须遵守的协议。

## 4. 示例内容设计

### 主示例：《大明末年危局》

这是机制验证用的游戏局势，数值不对应历史财政与兵力。时间展示为 1643 年起，每回合一周；使用虚构职位 NPC，避免把尚未考证的历史人物履历当作事实。

| 内容 | 首期设置 |
| --- | --- |
| 实体 | 玩家皇帝、财政官、前线将领；朝廷和敌对阵营；北京与前线地点 |
| 状态 | 国库 100、前线军饷 0、已用军费 0、赈济资金 0、军队忠诚 50、北京控制者为朝廷 |
| 数值范围 | 资金字段 0–1000，统一单位“财政点”；忠诚 0–100 |
| 初始记忆 | 军饷与赈济同时申请拨款；前线将领私有担忧，只对该角色可见 |
| 玩家动作 | 调拨军饷、拨款赈济、等待；拨款金额为 1–100 的整数参数 |
| NPC 行为 | 财政官优先候选为转移 10 点到赈济资金，要求国库充足且赈济资金低于 30；前线将领无固定候选 |
| 第一个事件：欠饷 | 军饷不足 10 且忠诚至少 5 时，忠诚减 5；可重复 |
| 第二个事件：支付 | 军饷至少 10 时，从军饷转移 10 到已用军费；可重复 |
| 第三个事件：失守 | 候选回合至少 8 且忠诚低于 40 时，北京控制者变为敌对阵营；不可重复 |
| 失败 | 北京失守，优先级 0 |
| 成功 | 第 12 回合后仍控制北京且忠诚至少 40，优先级 10 |

三个事件按上述顺序执行。欠饷检查在支付之前，避免支付后余额不足导致同回合被重复惩罚。已用军费表示支出累计，不把支出返还国库。

可达性设计检查：第一回合把 100 点全部拨给军饷，随后等待，能支付前 10 回合；第 11、12 回合忠诚分别降至 45、40，满足成功。一直等待且不拨军饷，则第 8 回合达到失守条件。以上是按规则进行的手工推演，实际程序验收时仍需验证。

这是基础结算样例，不代表完整历史模拟或最终可玩性。赈济目标与更多角色利益可在后续内容迭代扩展。

### 第二题材的最小验证剧本

采用虚构空间站：指挥官、工程师、能源分配与维修目标。使用相同的字段、动作与事件语义，证明引擎没有按皇帝、财政或北京名称分支。它是架构验证材料，不承担完整剧情内容制作。

## 6. 验收标准

| 编号 | 情形 | 必须得到的结果 |
| --- | --- | --- |
| V01 | 完整主剧本加载，新建两个会话 | 状态从初始值复制；两局互不影响 |
| V02 | 缺失字段、未知字段、重复 id、错误引用、错误参数类型 | 加载或输入明确拒绝，指出位置与原因 |
| V03 | 国库 100，玩家转移 30 | 本动作后国库 70、目标字段加 30；后续 NPC / 事件变化另列 |
| V04 | 玩家请求转移 130 或无权限动作 | 不改状态、不推进时间、不产生成功记录 |
| V05 | 一个动作的后续效果失败 | 该动作所有效果撤销，无部分扣费 |
| V06 | 两个行动竞争不足的同一资源 | 后执行者使用最新余额，不透支、不自动裁剪 |
| V07 | 等待、NPC 无合法候选 | 等待推进一回合，NPC 无动作，事件仍按规定扫描 |
| V08 | 一次性事件再次满足；事件执行失败 | 已成功事件不重触发；失败事件无局部效果且不标记成功 |
| V09 | 多个终局目标同回合满足 | 按优先级与声明顺序选一个结果；终局拒绝新行动 |
| V10 | 同会话 request_id 重复提交或更换输入 | 原输入返回原结果；更换输入报冲突；不重复结算 |
| V11 | 在事务提交前模拟持久化失败并重启 | 最后已提交状态保持可恢复，没有半个回合或半条存档 |
| V12 | 正常保存后恢复并继续 | 字段、回合、记忆、事件标记、终局与历史一致 |
| V13 | 私有初始记忆、字段、事件 | 无权限角色的上下文与玩家反馈不包含相关内容 |
| V14 | 主示例连续 12 回合 | 设计中的成功与失败路径可达，变化都有来源 |
| V15 | 加载空间站剧本 | 同一引擎可执行动作与事件，无题材专用判断 |
| V16 | 从空白用领域编辑器创建完整剧本 | 无需手写 JSON，可配置全部定义并初始化世界 |
| V17 | 保存未完成草稿，刷新并重开 | 服务端确认的编辑内容完整保留；无效草稿不能试玩或定稿 |
| V18 | 条件／效果类型错误、失效引用与删除依赖项 | 错误定位到具体编辑项；删除受阻；修复后可通过共享校验 |
| V19 | 修改草稿、撤销重做、双标签页保存 | 结果符合操作；旧 revision 不覆盖新内容，修改可保留 |
| V20 | 试玩、定稿、正式新游戏 | 同一规则执行路径；试玩隔离；新游戏与有效定稿快照一致 |
| V21 | 定稿后修改草稿，再读取旧游戏或检查点 | 当前局保持保存时定义，草稿变化不悄悄影响游戏 |
| V22 | 注册、正确／错误登录、退出与过期 | 真正验证凭据；有效会话才可访问；旧令牌失效 |
| V23 | 未登录直接请求私有入口，伪造 owner 或玩家 actor | 无法获得私人内容或改写归属，不能冒充 NPC |
| V24 | 账号 A 与 B 直接请求对方对象 id | 草稿、定稿、试玩、动作、保存、详情、恢复全部拒绝越权 |
| V25 | A、B 创建同名存档并查询列表 | 每人仅见本人数据；不同账号名称不构成身份关联 |
| V26 | 保存检查点，继续几回合，再恢复检查点 | 创建独立新会话并准确回到保存时状态；原游戏与检查点不变 |
| V27 | 退出重登、刷新浏览器、重启服务后读档 | 个人列表与检查点持久存在，可恢复并继续 |
| V28 | 重复保存或恢复请求 | 只创建一个检查点或恢复会话，重试返回原结果 |

| V30 | 客户端校验标记伪造、导入含 owner 或存档字段 | 服务端重新校验；拒绝无效定稿；导入不产生所有权 |
| V31 | preview 请求创建正式存档或访问他人定稿 | 拒绝；正式游戏只来自本人可用定稿 |
| V32 | CSRF、登录限流、Cookie／密码存储检查 | 符合 identity-and-saves.md；凭据不进入日志或响应 |
