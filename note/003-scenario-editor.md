# 003：专业剧本编辑器与创作域

状态：**设计中：重做创作交互，待用户确认，尚未实现**。
依据：[编辑器功能规范](../docs/scenario-editor.md)、[架构](../docs/architecture.md)、[DSL](../docs/scenario-schema.md)、[API](../docs/api-contract.md)。
依赖：001 的契约／定义校验／世界服务，002 的可信身份；004 是本项的后续示例消费者，不是本项前置模块。

## 1. 目标与分工

作者从空白或已有草稿，用自然语言批量生成关联内容，再通过内容卡片检查和微调完整剧本，显式保存、修复错误、独立试玩、定稿并开始正式游戏。所有 templates／drafts／releases 业务归创作域，包括此前放入 002 的草稿基础 CRUD、模板读取与复制、保存 revision／去重。

003 拥有前端编辑体验、创作对象及作者接口；001 拥有 DSL／定义语义、通用执行和世界持久化。创建 preview 时创作域检查草稿和已保存 revision，再调用世界域应用能力。身份域仅提供可信用户，创作域查询自己的 owner。具体数值／角色 example 在 004 中使用本项制作。

功能、控件属性、转换和异常交互的权威细节维护在 doc 第 1–12 节，本 note 记录设计输入、实施与可观察的验收。复制新草稿的 source 三选一、导出封装和请求大小等提案同步记录于 API，不保留旧待实现请求形状。

## 2. 实施与检查对应

### 本轮设计输入（2026-10-13）

用户要求采用创作工作区，不以大量输入框组成的表单作为主界面；先研究 AI Dungeon、WorldOS 与 AI 小说写作流程，再确认交互设计。以下内容分类来自本轮讨论，具体结构仍以 DSL 为准。

| 内容级别 | 作者需要决定的内容 | 说明 |
| --- | --- | --- |
| 必需 | 剧本名称、至少一个角色并指定玩家、至少一个可执行行动、至少一个成功或失败终局 | 标识由编辑器生成；终局不要求成功和失败同时存在；等待行动允许无效果 |
| 选填，推荐 | 世界背景、开场、时间设定、回合单位、叙事风格与视角、简介 | 内容可逐步补充；背景与开场不是两个重复的权威正文 |
| 选填 | NPC 角色设定 | 非玩家角色不是最小剧本必需；包含描述、性格、个人目标、阵营与关系 |
| 选填；启用后配置必需 | NPC 自主行为 | 指定执行角色及顺序、可用候选行动及具体参数；首期按顺序挑选合法候选，性格文字不自动产生行动 |
| 选填；声明后属性必需 | 数值与其他局势变量 | 资源、血量等整数，以及布尔、文本、实体引用；声明类型、初值、范围／单位或候选、归属和受众；当前不支持小数数值或任意公式 |
| 按玩法需要 | 行动参数、条件与效果 | 使用输入就声明参数；需要扣费、转移或改变状态就配置效果；条件可组合，效果有执行顺序；等待允许无效果 |
| 选填；创建后定义必需 | 事件 | 名称、触发条件、顺序效果、是否重复、受众；事件之间有处理顺序；不是只写一段剧情文字 |
| 选填 | 阵营、地点、实体关系 | 关系描述是背景；需要动态改变的信任或归属另声明局势变量 |
| 选填；私密内容受众必需 | 初始记忆、秘密与信息可见性 | 公开或指定角色；与客观状态分开；平台账号归属不充当世界中的可见角色 |
| 选填的补充 | 多结局、描述性世界约束 | 至少一个终局必需，更多结局可选且需优先级；强制约束由权限、范围和条件执行 |
| 编辑器提供并可调整 | 运行配置 | 无 NPC 时行为列表可空；记忆上下文窗口等固定结构项仍由编辑器提供合法值，不要求作者先填写长表单 |

以上是作者填写要求，不是 JSON 字段可任意省略：固定顶层栏目由编辑器生成，允许空的集合和字符串使用当前 DSL 的空值。所有已声明状态必须有合法初值。实体归属与平台账号的数据归属分开。

最小练习例：名为“夜间值班”的剧本，只有一名玩家、一项等待行动，以及第三回合结束的成功条件；不需要阵营、地点、资源、NPC 或事件。用于 003 的能力验收，不替代 004 的具体题材示例。

本轮先交付研究、交互方案与设计预览，不据此宣称生产编辑器或 AI 创作能力已经实现。

原型覆盖说明：首版“夜间值班”仅展示最小创作流程，未展开 NPC、局势变量、事件等完整卡片，不代表这些功能被移出 003。当前能力清单按 DSL 全部顶层大类核对；不是任意题材所有未来玩法的穷尽列表。

对话辅助定位：辅助作者创建和修改完整剧本，包括背景、世界书、NPC、局势变量、行动、事件和结局。用户可以从一个想法生成候选，也可以针对已有条目修改；两种入口共享同一工作副本。模型建议不直接成为运行事实，必须显示结构变化和引用依赖，由作者采纳后进行统一校验。复杂候选可跨多个对象，必须检查整组依赖，不能采纳引用尚未建立字段的孤立规则。

已完成公开资料研究，来源与限制见 [创作方式研究](../docs/research/scenario-authoring-review.md)。当前推荐提供两种入口：自然语言描述 → 生成大纲 → 调整大纲 → 成组生成细则 → 微调／整组加入 → 校验与试玩；或从空白完全手动创建。两种方式共享草稿并可混用，卡片用于创建、查看和微调。具体映射、渐进展开、同一份定义和生成边界维护在编辑器规范 1.1–1.3。真实作者生成纳入 003 必需范围，不再推迟为可选附加项；实际模型、候选契约和接口待详细设计。本轮不改变 DSL、数据库或生产 API。

追加设计输入：用户澄清“逐步累积”指每次描述后批量增加内容，一句话可能产生多名 NPC、多条事件及关联细则，不要求逐项点击创建。AI 负责提取、补全和关联；允许一次加入整组，不强制逐卡确认；也能通过下一句话修改待采纳候选或继续扩展既有草稿。缺乏决定性信息才提问，其他合理补足显示为生成假设。卡片展示顺序不得隐式改变引擎执行顺序，卡片只是当前 DSL 的视图。

范围调整：此前“人工编辑器首期、AI 后续”的拆分不符合本轮明确需求。003 完成条件增加真实自然语言批量生成与验收；001 的运行侧仍采用固定 NPC 候选，不因此接入模型自主裁决。模型 I/O 仅放应用层，候选受当前 DSL 与统一校验约束，不引入任意脚本、题材硬编码或另一份事实模型。

## 3. 验收标准

| 编号 | 实际操作 | 必须观察到的结果 |
| --- | --- | --- |
| E01 | 身份失效、他人 id、伪造 owner 直接调用创作接口 | 拒绝且不读／写他人内容；有效用户由服务端上下文确定 |
| E02 | 空白、模板、本人定稿创建；修改副本 | 独立草稿从 revision=0 开始；模板／定稿及其他副本不变 |
| E03 | 改显示名、复制条目、列表重排 | 标识稳定；复制对象新 id，关联引用保持；字段复制要求新 key；导入非法／重复标识可显式修复，无自动改绑 |
| E04 | 通过故事稿、世界条目和规则卡创建世界、全部实体、玩家与关系 | 无需手写 JSON；生成当前 DSL，搜索选择器的名称／类型／id 正确 |
| E05 | 公开／私有记忆和叙事编辑 | 受众互斥且非空；玩家视图过滤私有记忆，作者可编辑完整内容 |
| E06 | 每种状态／参数类型及非法数字、引用 | 出现对应控件；禁止无关属性；不舍入或截断；初值与字段同步 |
| E07 | 改类型、范围或候选后撤销 | 提示受影响规则，引用失配保留并定位；撤销恢复完整内容 |
| E08 | 嵌套条件、空 all／any、not、参数／turn | 树可增删复制排序；not 一子项；来源限制和空集合语义正确 |
| E09 | 创建三种效果并重排 | 转移同单位不同字段；事件无参数、效果无 turn；声明顺序保留 |
| E10 | 动作参与角色／参数／结果受众，事件和目标 | 各自独立保存；等待无效果；终局顺序／优先级与开关准确 |
| E11 | NPC 加入／移除／排序、多个候选与参数 | 候选映射和角色顺序一致；按权限／类型生成表单；空数组不生成行为 |
| E12 | 删除被引用角色／字段／动作／参数 | 列出全部依赖并可跳转；引用解除前阻止删除 |
| E13 | 连续文本、树转换、复制、移动、撤销重做 | 操作按规范合并；覆盖完整定义；revision 不回退，新修改清空重做 |
| E14 | 保存中继续输入、成功响应或失败 | 只确认提交快照，新输入仍未保存；不显示虚假的已保存状态 |
| E15 | 双页同 revision、离开未保存页面、另存副本 | 冲突不覆盖；本地保留；可留在页面／明确放弃／保存或复制 |
| E16 | 断网丢响应、退出／原账号重登、切换账号 | 原请求原正文重试；内容不丢失且不自动跨账号提交 |
| E17 | 修改后点旧问题、保存并校验／试玩／定稿 | 过期问题不误定位；新增修改取消旧 revision 后续执行；服务端重新校验 |
| E18 | 无效 JSON、超大文件、未完成封装、错误子结构／标识、平台字段 | 拒绝的文件不建草稿；已知栏目内未完成或错误结构可用领域操作修复并撤销；封装 valid 不可信；导出无平台或世界数据 |
| E19 | 两账号的列表／详情／保存／导入／导出／校验／试玩／定稿 | 逐入口直接接口验证；他人对象与不存在统一 404，不泄露数量 |
| E20 | 草稿／定稿／导入创建的重复请求、不同正文、数据库故障 | 相同只提交一次；不同正文冲突；对象与账本同事务，无半次写入 |
| E21 | 试玩动作、玩家／作者切换、编辑后重开 | 独立 preview，合法推进；拒绝不推进；轨迹仅本人 preview，来源变化明确 |
| E22 | 校验到定稿间出现并发保存，重试定稿 | 重新检查修订；不定稿另一内容；原请求只产生一份快照 |
| E23 | 定稿后改草稿、复制定稿、开始正式游戏 | 定稿和已有世界不变；新草稿独立；play 取本人定稿快照 |
| E24 | 窄屏及键盘完成树节点、顺序移动和问题跳转 | 所有必需操作可达，焦点与文字错误可识别 |
| E25 | 不手写 JSON，从空白创建中性练习世界 | 保存重开→修复问题→试玩→定稿→正式游戏，实际浏览器完成 |
| E26 | DSL／控件逐项对照、核心构建与回归 | 当前所有节点可表达；不会引入 UI／I/O 到核心；剩余缺口列明 |
| E27 | 从名字进入，写背景／开场，再逐步补世界书 | 无强制长问卷；只展开当前内容；选填缺失不阻断；重新打开保留原文字和实体，没有重复权威正文 |
| E28 | 切换规则摘要与高级条件编辑，修改故事中的资源描述 | 摘要与结构一致；全部当前节点可表达；文字改写不改变资源或执行结果；无需手写 JSON |
| E29 | 逐次新增 NPC、事件和变量，再在卡片内建立行为与引用 | 可任意顺序创作；未完成草稿可保存；缺口定位当前卡片；既有对象被复用；同类型执行顺序显式调整；撤销复合操作恢复全部关联变化 |
| E30 | 使用真实模型，将一段描述生成多名 NPC、多条事件及所需变量／行动 | 多类型候选成组展示；内部引用可解析，复用既有对象；默认可整组加入，无逐项填写或逐卡确认；统一校验错误不得冒充可玩结果 |
| E31 | 继续描述修改候选或增量扩展已有剧本，再采纳与撤销 | 显示新增／修改／删除及假设；未涉及对象和既有标识保持；采纳整组是一次可撤销编辑；可选部分采纳明确检查依赖 |
| E32 | 生成期间编辑、取消、超时、模型失败、并发保存、账号切换及越权请求 | 旧候选不能覆盖新内容；生成失败保留输入和草稿；取消不采纳；他人内容不进入上下文；模型失败不会退回要求逐项填表才算完成 |
| E33 | 自然语言生成大纲后微调再细化，或从空白完全手动创建并切换入口 | 大纲不冒充可执行规则；细化使用最新大纲；两种入口不清空内容或候选、不重复对象；手动路径不依赖模型可用 |
| E34 | 在生成候选、手动新增和已加入草稿中打开 NPC 并编辑七个分组，再细化／加入／撤销 | 不只提供名称与设定；性格、目标、关系、状态、记忆、行动与行为可达；已编辑详情不丢失；关联对象保持同一份事实；自主行为未启用时不会自动执行 |
| E35 | 一行属性声明、高级设置互切，输入整数／布尔／文本／实体引用及错误语法 | 解析摘要与实际字段一致；key 稳定；整数范围显式给出；非法输入保留并阻止保存／采纳，不执行代码、不丢失已有合法值；实体引用明确解析 |

定义校验的完整性与定位是 001 提供的前置能力，不以编辑器复制另一套语义来修补。原 V16–V21、V30 和相关作者入口隔离由本项承接；003 的中性完整流程是产品能力验收，004 的题材制作是其后的用户用例，两者均需要证据。
