## 1. 目标与范围纠正

本项是使用 003 的具体 example，不维护 DSL、校验器、模板业务、通用规则或编辑器实现。此前放入本项的契约、定义语义和错误定位任务归回 001；模板目录、草稿复制和全部作者接口归 003。

主示例为大明末年危局，第二示例为空间站维修。用同一个标准编辑器，从空白输入角色、状态、动作、事件、目标和私有记忆，完成两个可运行世界。004 的完成必须证明编辑器确实可用于创作和重开这些内容，不以导入既有 JSON 代替制作。

已有 scenarios JSON 和曾通过的规则路径测试仅为内容对照／工程夹具；它们并非“通过 003 制作”的成果，不能据此勾选本项完成。

## 2. 交付物

| 内容 | 要求 |
| --- | --- |
| 两个本人草稿与定稿 | 完整领域控件制作，保存重开、校验及定稿 |
| 导出的 scenario.json | 来自 003 的有效定稿前对应保存修订，不手写修改内容 |
| 作者说明 | 写明栏目操作、字段与单位、规则顺序、可达路径、私有信息和示例局限 |

| 试玩／正式运行证据 | 主示例两路径、第二题材两路径、私有信息过滤、快照隔离 |
| 联合存档证据 | 正式游戏行动→保存→重登→恢复新会话→继续，保留原分支 |

创作数据在本人服务端对象中，库内可交付材料只含当前 DSL 与说明。拟定目录 scenarios/examples/ming-crisis 和 scenarios/examples/station-repair；现有根目录 JSON 作为夹具保留，不能盲目覆盖依赖其固定规则 id 的测试。编辑器生成的稳定 id 与旧夹具可能不同，按名称、字段 key 和语义对应核对。

产物验收后可作为 003 的只读模板目录材料，模板标识与内部自动 id 独立。这里配置的是内容，目录读取和复制能力仍由 003 实现，不增加示例专用 API。
