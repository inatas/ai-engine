# 项目架构与领域边界

本文维护当前项目架构、业务域和协作边界。专题职责与阅读关系见[全局设计索引](README.md)。

回合交互的当前目标设计见[回合、场景与分支流转](turn-flow.md)：同时支持 action 自动推进和 scene 多轮互动后结束回合，剧情节点按条件分叉。现有程序的动作式回合是实施基线，场景式回合、运行对话与逐节点开篇尚未实现。两种模式均属于世界运行域，不新增题材专用业务域；模型输入／表达在应用层，节点流转、状态与权限裁决在纯计算核心。

## 1. 产品目标

采用 world engine + 自定义剧本。产品核心是玩家选择剧本、进行游戏并保存／读取游戏记录；登录默认进入“玩剧本”。内置剧本可以直接开始，本人定稿也可游玩，玩家不必先创建、编辑或定稿。创建／编辑剧本是独立的“创作”子功能，作者通过自然语言批量生成和编辑完整世界定义。[作者侧真实生成](scenario-generation.md)属于创作域的必需能力；运行侧首期使用结构化动作、固定 NPC 候选和可见结果，自由输入与模型提议运行行动属于后续能力范围。

玩家主流程为：登录 → 选择内置剧本或本人定稿 → 开始游戏 → 行动 → 保存游戏 → 重新登录 → 继续游戏或读档。创作流程为：进入创作 → 从空白或模板编辑 → 保存与校验 → 作者试玩 → 定稿 → 返回游玩入口选择剧本。两条流程共用引擎，保持独立界面、状态与权限。

## 2. 三个业务域

| 域 | 拥有的数据与职责 | 对外能力 | 规范 |
| --- | --- | --- | --- |
| 身份与访问 | User、AuthSession、匿名 CSRF 上下文、认证限流；建立可信用户上下文与访问原则 | 注册、登录、me、退出、CSRF 初始化 | [身份与访问](auth-and-ownership.md) |
| 剧本创作 | ScenarioDraft、ScenarioRelease、只读模板目录、作者生成额度元数据；编辑、保存、导入导出、定义校验调用、定稿与作者试玩入口 | 作者内容 API 与编辑器 | [编辑器](scenario-editor.md)、[作者生成](scenario-generation.md) |
| 世界运行 | WorldSession、TurnRecord、角色知识、SaveGame；初始化、结算、可见反馈、自动持久化和恢复 | 游戏、preview 运行与调试、个人存档 API | [运行机制](runtime.md)、[个人存档](personal-saves.md) |

所有权检查由拥有对象的业务域执行：身份域提供可信 user_id，创作／世界域用 id + owner 查询自己的对象。身份域不读取草稿或存档仓储；前端提交的 owner 和 actor 不成为权威身份。

[具体示例](custom-scenarios.md)消费标准编辑器，不构成独立业务 API 或数据库域。DSL 是引擎的输入契约，schema 位于 contracts、语义校验位于 engine；示例只填入具体内容，不实现或扩展另一套通用机制。

## 3. 核心与应用分层

| 层 | 职责 |
| --- | --- |
| apps/web | 身份界面、领域编辑器、游戏和存档展示；只消费有权限的 API 视图 |
| apps/server | NestJS 模块化单体；三个业务域及 PostgreSQL、认证、HTTP、事务等适配 |
| packages/contracts | 剧本、请求、响应视图和检查点的共享结构契约，不导出 ORM／应用类型 |
| packages/engine | 定义语义校验、初始化、条件／效果、NPC／事件／目标调度、角色信息过滤；纯计算 |
| scenarios | 受控示例和后续模板导出产物，实际私人内容由创作域持久化 |

engine 不访问用户、数据库、网络、时间或随机源。server 提供权威输入，调用 engine 后提交候选状态。storage、HTTP、日志、请求去重实现是基础设施，不单独拆成业务域；角色、记忆、叙事是世界运行能力，首期不分别建立独立服务。

工程依赖、具体技术及强制门禁只在 [技术方案](technical-stack.md)维护；本文件不复制包版本、配置或存档字段表。

## 4. 域间协作

创作域先保存草稿，在绑定的 revision 上调用引擎定义校验。定稿创建不可修改的 ScenarioDefinition 快照；世界域接受受控内置剧本或本人有效定稿，复制快照到独立 play 会话。直接游玩内置剧本不创建草稿或定稿，不放宽其他用户私人定稿的访问权限。

作者试玩入口属于创作域：检查本人草稿及已保存修订后，把有效快照交给世界域创建 preview。后续行动、角色视图、轨迹和会话持久化共用世界服务；返回创作工作区的轨迹仅供本人 preview，play 不允许调试和读取 NPC 私有信息。

创作域拥有定稿读取能力，世界域通过该应用能力取得定义，不直接改写草稿／定稿表；创作域调用世界域的 preview 创建能力，不直接结算。实现时由应用入口组合这些能力或注入窄接口，避免两个 NestJS 模块互相导入。领域数据之间传递公开 DTO，不传 ORM 对象。

正式游戏及恢复始终使用保存时定义，不读取编辑器当前内容覆盖已有局势。世界域在事务中提交状态与请求结果；检查点及恢复规则只在 [个人存档](personal-saves.md)维护。跨域没有微服务分布式事务，首期仍是同一应用和同一数据库。

## 5. 规则内容与机制

ScenarioDefinition 声明实体、字段、初值、动作、事件、目标和叙事。角色名字、财政／能源数值、成功路径归内容；条件求值、同单位转移、动作原子性、回合顺序和可见性归引擎。自由描述不隐式产生可执行效果。

规则不足时先在引擎规范设计通用能力，更新 DSL、编辑器控件及受影响内容，再验证。具体示例通过标准编辑器使用这些能力，内容不能嵌入题材专用执行代码。

作者模型在创作应用层生成候选世界定义，由作者成组采纳后通过统一校验；不改变引擎执行语义。后续运行模型也只在应用层提议行动或解释已提交事实，仍回到同一引擎裁决。模型调用不进入 engine；首期不建设独立模型网关、向量检索、多人协作、公开社区或额外插件框架。

作者生成绑定本人草稿与本地输入快照，只返回临时候选；生成、采纳与保存是三个独立动作。候选契约与版本／依赖／取消边界见[作者生成](scenario-generation.md)，生成接口由创作域消费身份与统一定义校验，不接触世界或存档仓储。

## 6. 规范唯一归属

[DSL](scenario-schema.md)维护数据形状与静态校验；[运行机制](runtime.md)维护结算与角色知识；[个人存档](personal-saves.md)维护检查点及版本恢复；[身份](auth-and-ownership.md)维护认证和访问原则；[编辑器](scenario-editor.md)维护创作交互；[API](api-contract.md)维护 HTTP 形状、响应与去重；[示例](custom-scenarios.md)维护具体世界内容及制作流程。

每次设计变化更新所属规范，其他全局文件用主题引用承接。架构文档独立说明当前有效设计及必要理由，不包含逐次实施历史、任务进度或运行结果。

[作者生成契约](scenario-generation.md)维护生成输入快照、候选、差异依赖与调用失败语义；不在编辑器、技术方案和 API 中重复维护第二套嵌套字段。
