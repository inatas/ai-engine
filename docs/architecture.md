## 1. 项目定位

项目采用 **world engine + 自定义剧本**，构建可以更换题材的 AI 文字交互游戏。

剧本是一份完整的世界定义包，包含世界背景、NPC、阵营、地点、规则、初始局势、记忆种子、事件、目标和叙事设置。World Definition、Character Schema、规则定义等均属于剧本内部的组成部分，不是必须由作者分别接入的独立系统。

world engine 读取剧本，维护世界事实、执行规则、推进时间、组织角色行为并生成反馈。玩家通过行动改变局势；后续角色行为与叙述应延续已经发生的变化。

项目必须同时支持：作者通过专业剧本编辑器初始化完整世界；玩家经过用户鉴权，保存与读取归属于自己的游戏存档。两项都纳入首期交付，不再以手写 JSON、匿名命令行或本地文件替代用户入口。

首个示例为《大明末年危局》，用于验证资源竞争、角色利益、条件事件和长期后果。背景与数值是游戏设计素材，不将人物名、财政逻辑或历史结果写入通用引擎。

AI Dungeon 仅作为[额外产品参考](research/ai-dungeon-review.md)。其协作叙事与本项目当前世界运行方案存在差异，参考机制不自动成为架构约定或首期实施要求。

## 2. 内容与机制的边界

| 事项 | 剧本负责 | world engine 负责 |
| --- | --- | --- |
| 世界 | 背景、事实、技术边界、时间尺度 | 加载、引用校验、时间推进 |
| 角色 | 身份、性格、目标、关系、初始知识 | 构造可知上下文，组织行为提议 |
| 状态 | 可追踪字段、类型、范围、初始值 | 权威状态、合法修改、持久化 |
| 规则 | 哪些人可做什么、条件、消耗与效果 | 条件求值、效果执行与状态校验 |
| 事件 | 何时触发、产生什么后果、谁能获知 | 调度、重复触发控制、结果记录 |
| 目标 | 成功与失败条件、优先级 | 条件评估、终局状态 |
| 记忆 | 初始事实与认知、可见对象、上下文偏好 | 记录事件知识、检索与构造上下文 |
| 叙述 | 语气、视角、开场与表达约束 | 基于已结算结果生成可见反馈 |

规则的内容由作者定义，规则的执行语义由引擎提供。例如“调拨军饷”是剧本动作，“转移两个数值字段之间的资源”是通用机制。修改题材不应要求在引擎里增加判断剧本名称的分支。

## 3. 三类核心数据

| 数据 | 内容 | 权威来源 |
| --- | --- | --- |
| ScenarioDefinition | 作者通过编辑器创建的完整世界定义、状态声明、规则与初始值 | 服务端校验后的定稿／试玩快照 |
| WorldSession | 所属账号、当前回合、字段值、角色已知事件、已触发事件、游戏状态 | 已提交会话数据 |
| TurnRecord | 请求标识、提议、裁决、字段变化、触发事件、可见范围、反馈 | 本回合提交记录 |

新会话从剧本复制初始状态，与其他会话隔离。运行中不得回写剧本初始值。展示文本与角色记忆均不能反向覆盖权威状态。

首期会话保存启动时的完整剧本快照，用于保持同一局规则稳定和恢复该局。快照不是旧格式兼容层：程序或 DSL 变更后，可以直接废弃并重新生成存档，不实现迁移、旧版解释器或双格式读写。

自动持久化世界载荷与手动检查点从第一天带 schemaVersion=1，只接受程序当前版本。破坏性结构或恢复语义变更递增版本；缺失或不匹配时明确拒绝。schemaVersion 与并发 revision、剧本 release_id 分别承担不同职责。

内容服务另维护 ScenarioDraft 与不可原地修改的 ScenarioRelease；账号体系维护 User 与 AuthSession；个人存档用 SaveGame 保存独立检查点。登录身份和 owner_user_id 由服务端建立，不允许作者通过 DSL 决定。

专业编辑器 → 本人草稿 → 校验与试玩 → 本人定稿 → 鉴权的新游戏 → 回合自动持久化 → 个人检查点 → 读取并恢复到新会话，是首期完整链路。

## 4. 世界运行与 AI 的职责

模型承担自由文本意图理解、NPC 行为提议、角色表达和结果叙述。模型不直接修改存储，也不能凭叙述创建资源或完成事件。

玩家与 NPC 提交同一类结构化动作。引擎根据剧本授权与规则裁决。语义约束如性格、时代风格由上下文引导和输出检查支撑；资源范围、实体引用、动作权限由程序硬校验。

自然语言自由度与可执行动作范围分开：玩家可以表达任意意图，当前剧本未定义的动作不会自动获得结算效果。新增玩法可先通过现有 DSL 表达；需要新机制时，在 note 中设计通用能力并同步更新 docs。

## 5. 模块与依赖

| 规划模块 | 职责 | 边界 |
| --- | --- | --- |
| editor | 领域表单、引用选择、条件与效果编辑、错误定位、试玩 | 不在浏览器直接结算或确立所有权 |
| content | 个人草稿、模板复制、校验、定稿快照 | 与 scenario 共用校验，定稿只写当前格式 |
| identity | 注册登录、登录会话与统一数据授权 | 用户身份与剧本角色分开 |
| scenario | 解析、规范校验、引用校验、初始会话构造 | 不推进回合 |
| rules | 条件求值、动作授权、效果执行、字段范围校验 | 不调用模型、不直接保存 |
| runtime | 编排玩家、NPC、事件、目标与回合提交 | 不包含具体题材规则 |
| characters | 角色可知上下文与行为提议 | 提议须回到 rules 裁决 |
| memory | 初始知识、事件知识与相关记录选择 | 记忆不能替代状态 |
| model | 意图、提议、叙述的模型调用与输出解析 | 不拥有状态写入权限 |
| narrative | 可见结果整理与反馈生成 | 只能描述已成立的事实 |
| saves | 本人检查点保存、列表、读取与恢复 | 全部操作检查归属，不接受客户端权威状态 |
| storage | 事务、内容、会话、存档与请求去重 | 提交完整数据，条件更新避免覆盖新状态 |
| interface | 网页输入、状态展示、个人存档与结果反馈 | 不自行结算规则，玩家视图过滤内部信息 |

应用入口先经 identity 校验，再调用 content、runtime 或 saves；editor 使用 content 与 preview 入口。runtime 使用 scenario / rules / characters / memory / narrative / storage，saves 使用已提交世界快照恢复会话。characters 与 narrative 在需要时使用 model。规则执行可脱离模型进行验证。

上述 runtime 包含应用层编排与纯计算结算两部分。独立 packages/engine 只承载语义校验、初始化、规则、固定 NPC 调度及结算；身份、模型调用、存储、请求去重与事务位于 apps/server。packages/contracts 提供 Zod 契约与推导类型。核心依赖和禁止 API 由 lint、包依赖检查、独立编译及 CI 强制，详见技术选型文档。

上述是职责划分，实现时允许合并小模块，不要求为每个模块建立服务或复杂框架。

| 目录 | 用途 |
| --- | --- |
| docs/ | 当前全局技术架构 |
| note/ | 每次迭代的实施项、决策、验证与结果 |

当前只存在文档；上述为已确定技术方案的目录规划，尚未创建程序包或配置。

## 7. 技术决策状态

| 事项 | 当前决定 |
| --- | --- |
| 剧本定义 | JSON 作为内部 DSL 与交换格式；作者主要使用专业编辑器 |
| 交互方式 | 首期同源网页编辑器、游戏入口与“我的存档”；动作表单输入，自由文本后续接入 |
| 鉴权 | 用户名／密码、服务端登录会话、Cookie、逐对象归属检查 |
| 实现语言 | 全 TypeScript，strict；pnpm workspace 组织 |
| 前端 | React + Vite + Ant Design |
| 服务端 | Node.js + NestJS，模块化单体、同源入口 |
| 数据契约 | Zod schema 与推导类型；服务端最终校验 |
| 持久化 | PostgreSQL + Prisma，事务保存草稿、会话和检查点 |
| 核心边界 | 独立 engine 包；lint、依赖检查、独立编译与 CI 强制 |
| 存档格式 | schemaVersion 从 1 开始，仅支持当前版本，无迁移 |
| 模型供应商 | 未确定；首期使用固定行为与结构化反馈，不依赖真实模型 |
| 兼容策略 | 直接破坏性更新，不维护旧字段、旧日志、旧剧本或旧存档格式 |

网页编辑器、用户体系和数据库事务替代原先的命令行与单文件方案。未来调整时直接同步规范和实现，不建立并存方案。

技术组合已确定；依赖版本、鉴权组件参数与真实运行命令在首期实施时锁定并记录，不以文档方案代替配置完成。

## 8. 首期边界与后续方向

首期交付专业剧本编辑器、注册登录与私有内容、完整世界初始化与回合结算、个人存档保存／读取／恢复。NPC 使用相同动作协议的固定行为来源，以验证调度；这不等于完成 AI NPC。

后续再接入自由文本、模型角色提议和叙述生成，继而检查长局记忆与可玩性。复杂节点图、多人协作、实时后台模拟、向量检索和社区发布不在首期范围；专业编辑器的基本领域操作与个人存档不推迟。
