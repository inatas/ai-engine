## 1. 会话初始化

先验证登录身份与定稿归属，校验完整剧本后复制定义为会话快照，复制 initial_state.values 与 memories。会话具有唯一 session_id，owner_user_id 来自登录身份，mode 为 play，turn 与 revision 为 0，status 为 active，已触发事件、回合记录与请求去重账本为空。

编辑器试玩以有效草稿快照初始化 mode=preview 会话，归属于作者，与正式游戏使用同一结算路径；preview 不进入正式存档列表。账号归属字段不来自剧本或客户端。

开场只显示允许玩家知道的内容，不推进时间，不暗中改写初始状态。不同会话之间不共享可变状态。

## 2. 会话数据

| 数据项 | 内容 |
| --- | --- |
| session_id / scenario_id | 会话身份与来源剧本身份 |
| owner_user_id / mode | 服务端归属与 preview／play 类型 |
| schemaVersion | 自动持久化世界载荷的必填格式版本，初始 1，只接受当前版本 |
| revision | 条件写入修订，防止并发覆盖 |
| scenario_snapshot | 本局完整剧本定义 |
| turn / status | 已提交回合数；状态为 active、success 或 failure |
| values | 按 state_schema 声明保存的当前字段值 |
| known_records | 角色可知的初始记忆与回合结果引用 |
| fired_events | 已成功执行的不可重复事件 id |
| terminal_objective_id | 终局目标，未结束时为空 |
| turns | 已提交 TurnRecord 列表，用于历史与追踪变化；恢复分支保留原来源 |
| processed_requests | 当前 session_id 范围的请求输入摘要及已提交结果，用于去重 |

首期用服务端数据库中的完整检查点恢复，不依赖重新执行历史事件。检查点恢复为新 session_id，revision 及请求去重账本重新初始化；历史记录保留，不把旧分支请求当成新分支请求。

核心结算位于独立 TypeScript engine 包；身份、模型、持久化与请求账本由 NestJS 应用服务适配。核心只处理显式输入并返回候选结果，不访问时间、随机数、网络或数据库，依赖边界按[技术选型](technical-stack.md)强制检查。

## 3. 回合顺序

1. 验证登录会话并检查 WorldSession 归属，检查当前 schemaVersion 与完整世界载荷；按 session_id 范围检查 request_id，已提交的相同请求返回原结果。相同标识对应不同输入时报冲突；新请求要求会话 active 且 expected_revision 匹配。版本门禁同样约束重复请求，不从旧格式账本返回缓存结果。
2. 解析玩家动作；网页动作表单首期提交结构化动作，玩家 actor_id 由该会话的 player 定义确认，不能切换到 NPC 身份。后续模型可映射到同一协议。
3. 复制状态，候选回合号为已提交 turn + 1。动作条件与事件、目标中的 turn 均读取这个候选值。
4. 校验玩家身份、动作授权、参数、条件及全部效果并执行。无效输入不保存回合、不推进时间。
5. 根据 simulation.npc_order 依次处理 NPC，每个 NPC 最多执行一个动作。首期候选基于当时的临时状态选择，后续模型提议也必须再次校验。
6. 按 events 声明顺序扫描条件与效果，处理重复触发标记；本轮不进行递归事件扫描。
7. 评估 objectives，按显式优先级确定终局。
8. 根据结果受众及字段可见范围生成角色可知引用；在同一数据库事务内条件更新 revision，将状态、回合号、事件标记、知识引用、TurnRecord 和请求结果一起保存。并发冲突整轮不提交。
9. 从已提交结果生成玩家反馈。首期为结构化摘要，后续可采用模型叙述。

玩家每次提交一个合法动作就推进一回合；等待动作同样推进。NPC 没有合法动作时记录无动作。终局后拒绝新请求；重复已提交请求仍可查询原结果。

## 4. 结算语义

动作是最小原子单元：以执行前状态复制临时副本，顺序应用效果，全部通过后才合入本轮状态。NPC 动作失败不撤销玩家已经合法的行动；事件效果失败也不留下局部修改。

多个角色竞争同一资源时，后执行者读取最新余额。固定顺序可解释且可重复，不做并发写入或同时行动冲突推演。

例如余额 100，玩家转移 30 后为 70；NPC 申请转移 80 会失败，余额仍为 70。若同一动作的第二个效果越界，第一个效果也必须撤销。

事件或 NPC 单项拒绝写入回合记录；无法构造一致状态的内部错误导致整轮不提交，原存档保留。首期不自动裁剪数值、补钱或更改动作参数以使其成功。

## 5. 记录、记忆与叙述

TurnRecord 包含来源 session_id、request_id、玩家输入、回合号、按顺序排列的动作裁决、事件裁决、字段变化前后值、结果受众和终局目标。拒绝项保留内部原因；对玩家只返回其有权限看到的内容。

已提交事实是记忆来源。角色上下文从自身设定、可见字段、初始记忆和可见回合结果构成。simulation.memory_recent_turns 为非负整数：选择最近对应数量回合的可见结果；初始记忆不因此消失。首期不做模型摘要、向量检索或自动传播秘密。

叙述只能解释已提交事实，不能创建新效果。模型角色提议也不能通过对话直接把不存在的人物、资源或控制权写入状态。

首期结构化反馈包含玩家可见动作结果、字段变化、事件、当前回合与终局。后续模型叙述失败时返回该摘要；重试叙述不会重做结算。未来实际模型接口和上下文协议由相应 note 提出并回写 docs。

## 6. 保存与恢复

成功回合自动事务保存本人 WorldSession。手动保存由服务端读取已提交 play 会话，检查所有权与 expected_revision，创建具名 SaveGame 检查点，包含剧本快照、状态和历史。客户端不能提供替代权威状态。

个人存档列表与详情始终按登录用户过滤。恢复本人检查点时创建独立新会话，不覆盖原会话，不重播事件，保持保存时的规则与世界事实。未登录或无归属权限时拒绝操作，详见鉴权与个人存档文档。

同一会话多标签页的竞争通过 revision 条件写入处理，只允许一个提交成功。首期仍为每局单玩家，不支持多人共同操作。事务失败保留最后已提交状态，重试不会重复扣费。

读取、继续、行动、保存与恢复先检查归属，再检查当前 schemaVersion，然后检查剧本快照、状态字段、事件引用及回合一致性。自动会话与手动检查点均覆盖；缺失、非法或不匹配版本明确拒绝，同版本损坏同样报错。破坏性更新后递增版本并重新创建当前格式数据，不实现兼容读取或迁移。

## 7. 错误处理

| 情况 | 处理 |
| --- | --- |
| 未登录、令牌失效 | 拒绝访问，重新登录；不返回私人数据 |
| 不属于本人 | 拒绝访问，不暴露该对象是否存在或其内部信息 |
| revision 冲突 | 不提交本轮或保存请求，要求重新加载当前状态 |
| 剧本结构或引用错误 | 拒绝加载，给出定义位置与原因 |
| 玩家意图或参数无效 | 拒绝本次请求，不推进时间 |
| NPC 无合法候选 | 记录无动作，继续本轮 |
| 动作效果越界 | 撤销该动作全部效果，记录拒绝 |
| 事件效果失败 | 撤销该事件效果，不标记已触发 |
| 重复请求 | 返回原结果；输入不同则报冲突 |
| 保存失败或内部一致性错误 | 整轮不提交，保留原存档 |
| 反馈生成失败 | 保留已提交结果，允许单独重新展示 |
| 版本缺失、非法或不支持 | 返回 checkpoint_version_unsupported，不创建或推进会话 |
| 同版本载荷损坏、版本列与载荷不一致 | 返回 checkpoint_invalid，保留原数据，不部分恢复 |
| 格式或恢复语义改变 | 递增 schemaVersion，重新创建当前格式会话，不走旧版兼容路径 |

## 8. 可追踪性

世界状态变化与运行诊断分开。回合记录说明发生了什么及为何发生；诊断日志记录加载、耗时、保存和异常。日志格式可直接调整，不作为稳定外部接口。

首期以规则执行与恢复正确性为主要验证点。真实模型接入后，再记录调用次数、用量、等待时间和无效输出率；当前不预设供应商与价格。
