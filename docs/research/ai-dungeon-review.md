## 1. 判断

可以借鉴其“用户剧本模板 → 个人游玩实例”的产品结构，不能据此确认它与 WorldOS 使用同样的引擎。[官方 Scenario 说明](https://help.aidungeon.com/faq/what-are-scenarios)将 Scenario 定义为创建 Adventure 的模板，支持用户创作、发布与多次开局。

AI Dungeon 官方将自身定位为协作叙事；其记忆系统说明中特别区分了 Voyage 跟踪血量、背包等游戏状态的方式。[官方 Memory System 说明](https://help.aidungeon.com/faq/the-memory-system)。因此，不应把它的公开能力等同于默认存在一个全面数值模拟器。

产品主页在本次文本访问中仅返回连接提示。下述事实以官方帮助资料为依据，不宣称已验证登录后的编辑器界面、发布效果或历史长局质量。

## 2. 可核实的机制

| 官方机制 | 含义 | 对本项目的启示 |
| --- | --- | --- |
| Scenario 与 Adventure | 模板和每次游玩分开 | 保留定义与会话快照隔离，避免玩家进展修改原作 |
| Story Cards | 人物、地点与概念信息按触发词进入上下文 | NPC 数据需要按需供给模型；卡片不是独立 Agent 的证据 |
| Plot Components | 分开生成指导、核心设定、摘要和作者风格指导 | 不把全部背景塞进一个固定 Prompt |
| 自由输入与修正 | Do、Say、Story、Continue，以及编辑和重试 | 玩家需要表达与纠错能力；重试不应重复执行资源结算 |
| 开局定制 | 问答占位、角色创建与选择不同开场 | 同一世界可以产生不同个人开局 |
| 记忆与上下文观察 | 历史压缩、相关记忆检索与上下文使用信息 | 需要知道模型实际收到什么，以及被裁掉了什么 |
| 发布与非列表分享 | 内容可供他人使用，发布与继续编辑可分离 | 私有定稿不能被当成完整 UGC 分发闭环 |
| Scripting | 输入、上下文与输出的生命周期扩展点 | 先保留扩展边界，不急于开放任意用户代码 |

Story Cards 机制来源：[官方说明](https://help.aidungeon.com/faq/story-cards)。Plot Components 来源：[官方说明](https://help.aidungeon.com/faq/plot-components)。输入与修改来源：[官方游玩说明](https://help.aidungeon.com/faq/how-to-play)。脚本扩展点来源：[官方 Scripting 文档](https://help.aidungeon.com/faq/how-do-i-write-scripts-and-use-scripting)。

上表的本项目建议是设计推论，不是对 AI Dungeon 数据库、调度方式或 NPC 自主行为的断言。不复制其具体上下文排序、额度、触发窗口和脚本执行配额为本项目标准。

## 3. 差异与候选想法（未采纳为需求）

| 差异 | 可能影响 | 可选研究方向 |
| --- | --- | --- |
| 要求每个剧本都有可结算动作及终局目标 | NPC 对话、悬疑短篇和开放探索被迫配置数值游戏 | 允许轻量叙事定义，动作、数值、事件及终局按玩法选用 |
| 编辑器先暴露所有底层结构 | 作者尚未写故事就需要理解引擎字段 | 基础创作与进阶规则分层，使用同一份 DSL |
| 没有设定卡与生成指导分层 | 上下文膨胀，NPC 容易丢失重要信息 | 增加 plot、story_cards 与明确的上下文装配规则 |
| 只保留近期回合记忆 | 历史承诺离开窗口后没有稳定补充机制 | 首期保留重要事实与可解释筛选，模型阶段再加摘要及检索 |
| 玩家角色与开场固定 | 模板重复游玩变化有限 | 先加受限开局参数，复杂角色创建与开场分支后续实现 |
| 只有动作表单与结构化反馈 | 基础机制可验证，但不能代表可玩的 AI 叙事产品 | 将真实模型、自由输入与叙事质量列为单独必验里程碑 |
| 全部内容仅本人可用 | 已有创作工具，尚无用户之间的内容流通 | 增加发布／下架／分享／改编的全局设计，分发安排后续迭代 |
| 只验资源与存档，没有叙事指标 | 测试通过仍可能角色混乱、承诺丢失 | 加入角色一致性、事实延续、设定命中与上下文预算验收 |

## 4. 采用边界

AI Dungeon 的自由协作叙事与本项目当前的世界状态及行动结算有明显差异。不为贴近参考而改变首期方案，也不将它的组件名直接变成本项目必填字段。

可保留的通用借鉴是：剧本与游玩实例分开、编辑后能校验和试玩、角色信息要有明确来源与可见范围。当前设计已有相应职责，不需要另建开发项。

设定卡、分层生成指导、参数化开局、自由输入、公开分发和改编仅为候选方向。将来确有产品需求时再设计并写入对应 note，目前不规定实现阶段、优先级或验收门槛。

NPC 卡片不证明独立 Agent 调度；公开模板也不代表玩家存档公开。这些是阅读参考时需要区分的概念，不自动产生新模块。

## 5. 当前项目保持的方向

保留 world engine + 自定义剧本、平台账号与游戏角色分离、剧本快照与会话隔离、存档归属检查、受限 DSL、通用效果和破坏性更新策略。

本次额外参考不改变首期的字段、输入协议、结算方式或验收范围。是否增加协作叙事玩法，留待明确需求后决定。
