## 无剧透介绍

玩家是战时密码破译设施中的工作人员，被怀疑盗走计算设备的一枚部件。面对审讯，可合作、隐瞒、误导或寻找脱身机会。谈话、线索传递与行动留下的痕迹影响后续判断和结局。

这是谍报悬疑与自保博弈，不是玩家扮演侦探寻找未知凶手的传统案件。相比只有简介的庄园样例，它的优势是实际剧情、条件和结局完整可读。

## 作者研究：包含结局剧透

源码的核心信息不是单一调查分数。它分别追踪部件是否取得、归还或丢弃，是否破窗、鞋上是否有泥、是否承认受勒索、是否嫁祸 Hooper，以及向 Hooper 传递的线索类型。强硬与回避倾向另有数值。

剧情提供审讯、与 Hooper 的互动、夜间行动、处理部件及最终对质等节点。结束段落包括逃离营地、暂时脱身、返回藏匿处被识破，以及被拘押；部分结局正文还依赖此前选择。这些不是自动对应本项目二元胜负，需要先明确改编的终局分类。

## 我们的框架如何承接

依据：[剧本 DSL](../scenario-schema.md)、[运行机制](../runtime.md)、[编辑器](../scenario-editor.md)。

| 原作内容 | 转换方向与实际限制 |
| --- | --- |
| 人物、背景、秘密 | 角色与初始私有记忆；秘密正文不能随公开角色描述泄露 |
| 部件、痕迹、承认与嫁祸 | 逐项 boolean／integer／entity_ref 状态，不压成“推理进度” |
| 对话与行动选择 | 带条件的动作；对话交换的步数与世界回合不能未经设计直接一比一转换 |
| 场景跳转及访问次数 | 明确的场景状态、访问标记；Ink 的跳转、访问计数和函数不能直接交给现有引擎执行 |
| 条件证词与剧情正文 | 当前运行反馈只有结构化结果，须设计通用正文交付、触发与受众机制 |
| 条件结局 | 目标条件与优先级；同时需要保留不同结局的叙述和选择后果 |
| 自由输入 | 原作没有 AI 自由对话，不能“照搬”得到；需应用层映射为受约束的谈话／行动意图 |

改编建议：保留原作事实、关键分支与结局，允许玩家用自己的话回应或提出行动。AI 可以理解意图、表达证词，但不能更换部件位置、任意新增关键证据、改写秘密或直接判定胜负。状态变化仍由引擎校验执行；无法支持的意图明确反馈，不强行归类。

当前文件是完整素材归档，不是可导入的 scenario.json。正式改编前还须逐场景阅读、形成真相／角色知识／线索／分支对应表，并将运行侧缺口单独设计记录；不把故事专用代码塞进 engine。
