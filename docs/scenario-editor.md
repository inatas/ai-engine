# 专业剧本编辑器

更新日期：2026-10-12。状态：设计依据，尚未实现。  
关联文档：[全局架构](architecture.md)、[剧本 DSL](scenario-schema.md)、[鉴权与个人存档](identity-and-saves.md)、[应用接口契约](api-contract.md)。  
关联开发项：[首期实施 note](../note/001-world-engine-foundation.md)。

## 1. 定位与完成条件

剧本作者通过专用编辑器初始化完整世界定义包。编辑器覆盖世界背景、NPC、阵营、地点、规则、记忆、初始状态、事件、目标与叙事设置，生成引擎可运行的 ScenarioDefinition。

本项目将“专业”落实为领域编辑能力：实体引用选择、角色与关系编辑、类型化状态配置、条件树和效果编辑、依赖检查、定位错误、试玩和结算追踪。JSON 是交换格式；作者不需要手写 JSON 才能建立一个可运行世界。

首期采用内置网页编辑器，和游戏入口使用同一用户体系、同一后端校验与同一 world engine。外部编辑器的 JSON 导入是辅助方式，不作为专业编辑器目标的替代交付。

## 2. 用户流程

1. 注册或登录，进入“我的剧本”。
2. 从空白、示例模板或 JSON 导入创建个人草稿。复制模板创建新的实体内容包，不修改共享模板。
3. 按栏目配置世界与玩法，保存到服务端；未完成定义可以保存为草稿。
4. 查看错误与警告，点击问题跳转到对应实体、字段或规则节点。
5. 对完整有效的草稿启动试玩，检查动作结算、事件顺序、目标和角色可知信息。
6. 创建可运行定稿，服务端保存独立的定义快照。
7. 从定稿启动正式游戏，生成归属于当前账号的 WorldSession；运行数据不写回草稿。

定稿在首期仅本人可用，不代表发布到社区。后续编辑草稿不改变已经创建的定稿或游戏存档；新定稿使用新的 release_id，不引入旧格式兼容解释器。

## 3. 编辑工作区

| 区域 | 作者操作 | 生成或维护的定义 |
| --- | --- | --- |
| 世界与玩家 | 背景、时间尺度、技术边界、玩家角色选择 | world、player |
| 实体库 | 添加 NPC、阵营、地点；修改名称、身份与目标 | entities |
| 角色与关系 | 性格、目标、归属、关系目标选择、初始知识 | characters、initial_state.memories |
| 状态面板 | 类型、单位、边界、可见对象、初始值与控制者 | state_schema、initial_state.values |
| 动作编辑 | 参与角色、参数、前置条件、效果顺序与受众 | actions |
| 条件编辑 | 组合 all / any / not，选择比较操作及字段、参数、常量 | conditions |
| 效果编辑 | add / set / transfer；字段与数值来源选择 | effects |
| 事件编辑 | 条件、效果、执行顺序、重复策略与受众 | events |
| 目标编辑 | 成败条件与优先级 | objectives |
| 演化设置 | NPC 顺序、候选动作与上下文上限 | simulation |
| 叙事设置 | 开场、风格、视角 | narrative |
| 问题面板 | 定位引用错误、类型错误、范围错误与规则提示 | 校验结果，不进入剧本 |
| 试玩面板 | 玩家动作、角色视图、状态变化、事件轨迹、终局 | 独立试玩会话，不改变初始状态 |

条件和效果使用结构化控件；可视化节点图不是首期必要条件。领域表单与组合编辑器必须可完整表达首期 DSL，不以大型文本框代替规则编辑。

## 4. 引用与编辑行为

实体名称可修改，稳定 id 不随名称改变。选择器显示名称与类型，但提交 id。状态与动作选择器按当前操作的类型过滤，避免作者选择不能执行 transfer 的字段。

删除被引用的实体、字段或动作前，展示引用位置。首期默认阻止删除，作者先修改引用；不悄悄删除依赖规则。调整类型或范围使已有定义失效时，保留内容并标出错误，阻止试玩与定稿。

提供本次打开编辑器后的撤销与重做；撤销后的内容仍通过正常保存请求同步。撤销历史属于编辑体验，不作为运行规则或兼容数据保存。

## 5. 草稿保存与冲突

ScenarioDraft 包含 draft_id、owner_user_id、document、revision、created_at、updated_at。document 允许未完成字段，不能直接作为正式引擎输入。

首期提供显式“保存草稿”，并区分未保存、保存中、已保存与失败状态。离开有未保存修改的页面时提示。跨刷新恢复的是最后一次服务端确认的草稿，不宣称未发送修改已持久化。

每次修改带 expected_revision，服务端按当前用户与草稿归属检查后条件更新。多标签页出现修订冲突时，不覆盖较新内容；保留本地修改并让作者重新读取或另建副本。

保存请求另带 request_id，丢失响应时按原输入重试。校验、试玩、定稿先保存本地修改，再绑定已确认的修订；过期校验结果不能沿用到后续修改。

revision 用于并发控制，不用于支持旧版 DSL。自动保存可后续加入，但首期必须具备显式保存与可靠的保存反馈。

## 6. 统一校验与定稿

浏览器做即时输入提示，服务端共享 scenario 校验器作最终判断。试玩和定稿都必须重新校验同一份提交内容，不信任客户端“校验通过”标记。

错误结果至少包含 severity、definition_path、message、相关实体或规则 id。错误阻止执行；警告提醒作者注意叙述约束、未使用字段等问题，不冒充目标可达性的数学证明。

定稿时提交 expected_revision；服务端在同一事务内确认草稿修订、验证完整定义、生成 ScenarioRelease 并保存快照，避免校验内容与定稿内容不同。

ScenarioRelease 包含 release_id、source_draft_id、source_revision、owner_user_id、definition、created_at。定义快照不可原地修改；修改草稿后生成新定稿。release_id 是内容身份，不是兼容分支。

账号归属、草稿修订和定稿记录保存在内容服务，不加入作者可导入的 DSL。导入文件声明的所有者、存档或登录信息一律不能决定权限。

## 7. 试玩与正式游戏

草稿试玩要求有效定义，创建带 mode=preview 的独立 WorldSession，绑定该次校验通过的草稿快照。修改草稿后需重新启动试玩，旧试玩不被实时改写。

试玩使用正式引擎的初始化与结算路径。作者视图可查看完整内部轨迹，玩家视图按角色信息范围过滤；两个视图明确切换，不能把调试数据作为玩家接口的默认响应。

preview 会话不进入个人正式存档列表，首期禁止将其保存为正式存档。正式游戏必须从本人可用定稿初始化，mode=play，并支持个人保存与恢复。

## 8. 导入与导出

导入 JSON 先解析到个人草稿，再显示校验结果。合法 JSON 但定义不完整时可修正；无法解析时返回位置与原因，不建立可运行定稿。

导出只包含当前 ScenarioDefinition 内容，不包含用户凭据、数据库归属信息、试玩会话或游戏存档。导入导出遵守当前 DSL；破坏性调整后不提供旧格式转换器。

## 9. 首期验收边界

作者应能只用表单、引用选择器、条件和效果编辑器从空白创建完整世界，保存并重新打开，修复被定位的错误，试玩并定稿，再启动正式游戏。示例内容用于验证，不是唯一可编辑题材。

首期不包含多人共同编辑、公开社区、复杂可视化关系图、AI 自动写剧本、素材管理与外部专业软件插件。上述不影响完整的首期编辑流程。
