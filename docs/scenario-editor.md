# 专业剧本编辑器与创作域

本文维护作者功能、交互和创作事务。DSL 与校验规范见 [scenario-schema.md](scenario-schema.md)，输入快照、候选数据及模型失败规则见 [作者生成契约](scenario-generation.md)。交互依据见 [创作方式研究](research/scenario-authoring-review.md)。

待实施扩展：[回合、场景与分支流转](turn-flow.md)。作者需要编辑场景地点／人物、剧情节点、推进模式、开篇正文或 AI 写作规则及后备正文、进入／结束条件与效果、可用互动、带条件与优先级的后继边。分支属于内容引用，不把节点目录顺序当成剧情顺序；过渡节点只允许结束操作。自然语言批量起稿与精确手动编辑消费同一新契约，试玩必须覆盖场景中途状态与不同后继路径，不能只检验一条线性路线。

## 1. 完成目标与工作区

编辑器仅位于独立“创作”入口，登录首页及玩家游戏／存档入口由[架构](architecture.md)定义。创作界面只管理草稿、定稿和作者 preview，不混入正式游戏与存档列表。切换到游玩时保留同账号未保存的编辑、候选和撤销历史；不会隐式保存或丢弃。正式 play 与 preview 状态分别持有，切换不会用试玩覆盖当前游戏。

作者可从空白或已有草稿，通过自然语言成组生成并逐步扩展完整定义，查看或微调后保存，修复错误，试玩后创建本人定稿并启动正式游戏。全部当前 DSL 必须有领域控件，作为精确编辑的辅助入口；JSON 只用于交换和查看。

| 页面／区域 | 必需内容与操作 |
| --- | --- |
| 我的剧本 | 本人草稿名称、最近更新时间、revision；创建空白、复制模板、导入、打开；区分本人定稿入口 |
| 编辑器顶栏 | 草稿名、保存状态、已确认 revision；保存、撤销、重做、校验、试玩、定稿、导入／导出 |
| 创作导航 | 同一工作区的内容目录，定位背景、角色／NPC、局势、行动、事件与结局；试玩按需打开 |
| 中央内容 | 提供“自然语言起稿”和“从空白手动创建”两种入口；描述先生成可调整大纲，再成组细化；内容卡片用于手动创建、查看和微调 |
| 问题区 | 服务端结构／语义问题，按栏目归类，点击展开具体对象并聚焦属性或规则节点 |
| 试玩区 | 独立 preview 的玩家界面和作者轨迹；显示来源草稿 revision 及“已与当前编辑内容不同”标识 |
| 我的定稿 | 名称、来源修订、创建时间；只读查看、从定稿复制新草稿、导出、前往游玩入口 |

窄屏把目录和问题区折叠为可打开的面板，不隐藏必需功能；所有新增、顺序移动、树节点编辑和校验定位均支持键盘操作。局部属性控件有可关联标签，校验焦点移动后同时显示文字原因。

首期不提供删除草稿／定稿、协作编辑、公开发布或复杂节点图。真实作者侧 AI 批量生成属于创作域必需能力。本地工作副本、生成候选、撤销历史、试玩结果和服务端已保存快照是不同状态。

### 1.1 创作流程与信息层级

从一个名字进入工作区即可，不强迫作者先完成问卷。作者可选择自然语言起稿：描述世界、角色或冲突，AI 先生成大纲，再在作者调整的大纲基础上细化多项关联内容；下一段描述可增加、修改或细化这批内容，剧本按批次生长。也可从空白完全手动创建，两种入口随时混用，共享同一份工作副本和撤销历史。背景、世界书与规则属于同一工作区；AI 路径不要求逐个创建 NPC／事件或逐卡填写细则，手动路径不依赖模型可用。非阻断的创作清单提示必需内容缺口，不要求把选填内容全部补齐。内容分类维护在第 1.4 节，有效性由统一 DSL 校验决定。

| 内容类型 | 默认体验 | 按需展开 | 当前 DSL 对应 |
| --- | --- | --- | --- |
| 故事稿 | 世界背景的大面积段落写作；可切换开场文本 | 世界时间、回合单位、描述约束、叙事风格与视角 | world、narrative；名称与简介位于剧本资料 |
| 世界书 | 角色、阵营、地点的可浏览条目；打开单项编辑正文；可指定玩家 | 性格、目标、实体关系、阵营归属、初始记忆和受众 | entities、player、initial_state.memories |
| 规则 | 按“行动、局势、事件、结局、NPC”组织的语句式卡片 | 当前卡片的条件树、参数、顺序效果、可见性和类型属性 | actions、state_schema、initial_state.values、events、objectives、simulation |
| 试玩 | 玩家反馈、可选行动及当前回合；可返回对应规则修正 | 作者调试轨迹与状态变化；来源修订、重开 | 独立 preview，不写回 ScenarioDefinition |

手动“添加内容”作为辅助入口，可选背景／开场、角色／NPC、阵营、地点、关系／记忆、局势变量、行动、事件与结局；新卡片出现并获得焦点，其他卡片默认折叠为名称、摘要和完成状态。生成或手动编辑的内容都可保留为未完成草稿，缺口在当前内容显示；试玩与定稿仍要求整个定义有效。内容目录按类型聚合，卡片数量增加后可快速定位，不把全部对象展开成一个长表单。

NPC 卡先写名称和角色描述，再按需增加关系、私有记忆或行为。行为面板直接选择既有行动，也提供“新建行动并关联”的局部入口；关联多个当前结构的整次操作纳入同一撤销记录。事件卡先写名称，再补“何时发生／发生什么／是否重复／谁能知道”。引用不存在的数值时明确提供“新增变量”，作者定义并确认后才建立引用，不由正文自动生成。

卡片是编辑器视图，不新增 blocks 字段或另一套执行格式。NPC 设定和行为分别映射实体与 simulation，却显示在同一卡片中；新建时不默认启用自主行动。展示位置与执行顺序分开：按固定内容类型分组，同类型条目默认沿用定义列表顺序；NPC、候选行动、事件、效果和目标的执行顺序有明确的局部操作。不能用跨类型视觉拖动暗中改变运行顺序，筛选及展开状态也不改变定义。

复制卡片沿用第 2 节的稳定标识与引用规则，复制复合内容时显示关联范围。删除、依赖定位和撤销仍按第 8 节执行；引用目标可以由多个对象复用，不把同一 NPC 或变量复制成多个事实副本。

故事稿是现有文字字段的作者视图，不是新增一份独立小说正文。背景与开场分别保存，禁止将同一段内容复制为两份权威设定。首期使用纯文本段落，不增加富文本 AST、章节或独立作者笔记存储。世界书标题和正文直接编辑原实体字段；筛选、折叠、当前工作区等只属于界面状态，不写入 DSL。

文字中出现角色名称，不自动创建实体引用或数值规则。关系、受众、玩家与行动权限仍通过选择既有实体生成明确 id 引用。规则卡的自然语言摘要由当前结构生成，不另存一份摘要作为执行依据；输入不完整时保留为未完成工作副本并显示缺口。

### 1.2 规则卡与高级编辑

行动卡默认展示“谁可以【行动】；当【条件】；依次【后果】”。点击片段才打开当前内容的编辑面板。新增卡先选择规则类别和名称，再补最少必要项；不预先生成大量空输入框。等待提供显式的无条件／无效果设置，不悄悄制造资源字段。

局势卡展示字段、归属、类型、初值与受众；事件卡展示触发与后果；结局卡展示判定、成功／失败和优先级；NPC 卡展示执行顺序和候选行动。参数类型、条件组合及全部 DSL 节点仍可通过局部高级面板编辑，具体约束按第 3–7 节执行。高级面板是同一结构的另一视图，不是另一种剧本格式，也不能要求作者手写 JSON 才能完成高级功能。

问题按作者语言描述，例如“等待还没有允许执行的角色”，点击直接定位该卡片的权限片段；JSON Pointer 仅用于内部定位和高级查看。统一校验不证明目标必然可达，创作清单不能冒充服务端校验结果。

### 1.3 自然语言批量创作

自然语言流程为“描述 → 生成大纲 → 调整大纲 → 生成／微调细则 → 整组加入 → 保存、校验与试玩”。同一句话允许提出多个 NPC、多个事件及其关系，细化阶段批量补充变量、行动与关联规则。候选范围覆盖当前 DSL 的背景、开场、全部实体、关系／记忆、局势与初值、行动、NPC 行为、事件、终局和运行配置；模型不能生成当前引擎不支持的执行机制。

大纲展示世界前提、玩家身份、角色群、核心冲突、事件方向、主要玩法与结束方向，可以用下一段描述调整，也可在条目上微调。它是作者规划的候选视图，不是已经可执行的剧本。生成细则时使用最新大纲及现有草稿；未补齐的内容可以加入为未完成草稿，仍需显示缺口。大纲采纳后映射为当前 DSL 的背景、实体描述及未完成规则，不新增独立大纲或章节事实模型；采纳前的候选编辑状态不构成新的持久化剧本格式。

手动路径允许从空白逐条创建，并与 AI 路径组合：可手动修改生成条目，也可让 AI 对手动建立的内容继续补充；切换模式不清空草稿、输入或未采纳候选，不重复创建既有角色及规则。生成返回仅提供新候选，不覆盖用户手动改动。

新增世界可从一个想法生成完整候选；已有剧本默认增量扩展，仅修改作者要求的范围，复用已有对象与稳定标识。生成时给出新增／修改／删除的分类摘要、关联影响和 AI 补足的假设，细节按需展开。描述充分时不追问每一个属性；缺少决定性信息或表达存在实质冲突时才提出集中问题，仍保留已生成内容。

作者默认可以一次加入整组，无需逐卡确认或手填每个条件。也可以继续说“增加两名有矛盾的 NPC”“把停电改成第三回合触发”，更新待加入候选；已经加入后的描述则形成下一组变更。支持拒绝整组和可选部分采纳，部分采纳须检查依赖，显示必须一起加入的变量／动作／引用，不能产生孤立规则。

一次整组采纳是一次可撤销的本地编辑，不自动保存、试玩、定稿或发布。自然语言用于生成明确的定义结构；只有已采纳并通过统一校验的结构才可运行，故事描述本身不执行。生成不会直接改变正在运行的世界或不可变定稿。

候选绑定生成时的本地内容版本；生成期间编辑后，旧建议标记过期，不直接覆盖新输入。生成失败、取消或超时保留描述与原草稿，允许重试；校验失败显示问题，可继续描述让 AI 修正，也可手动微调，不能冒充有效结果。模型上下文仅使用当前作者有权限的草稿和选定内容，不读取其他用户内容或玩家私密会话。

实际模型 I/O 与候选组装属于服务端创作应用层，engine 只参与统一定义校验。源快照、两类候选、改写范围、依赖组、取消／失败及成本以[作者生成契约](scenario-generation.md)为唯一规范，HTTP 形状维护在 API 第 3.1 节。供应方与模型是应用层适配选择；预置候选只用于交互演示，不能替代真实生成。

生成前建立本人草稿；之后可把未保存工作副本作为上下文，不因生成而暗中保存。界面明确显示此次会新增／改写的范围，重名对象要求选择。生成时草稿或候选发生修改、保存、撤销／重做，旧响应均标记过期；不自动重基。取消后迟到响应也不采纳。

整组采纳是一次可撤销本地编辑。部分采纳先显示必须同时加入的关联组，不能只复制 NPC 名称而遗漏字段、初值、行动或受众。校验缺口允许形成未完成草稿，问题与“可试玩”状态分开；未知执行字段或新悬空引用不能靠标成草稿绕过。刷新会丢失未采纳候选，界面提示采纳并保存，不显示已云端保存。

### 1.4 作者填写要求与创作清单

| 内容级别 | 作者需要决定的内容 | 约束 |
| --- | --- | --- |
| 必需 | 名称、至少一名角色并指定玩家、至少一项行动、至少一个成功或失败终局 | 标识自动生成；终局不要求成功与失败同时存在；等待可无效果 |
| 选填，推荐 | 背景、开场、时间设定、回合单位、简介、风格与视角 | 可逐步补充，背景与开场分别保存 |
| 选填 | NPC 描述、性格、个人目标、阵营与关系 | 非玩家角色不是最小剧本必需 |
| 选填；启用后配置必需 | NPC 自主行为 | 角色顺序、候选动作与完整参数；性格文字不自动产生行动 |
| 选填；声明后属性必需 | 整数、布尔、文本、实体引用状态 | 合法初值、类型、范围／单位或实体候选、归属与受众；不支持小数或公式 |
| 按玩法需要 | 动作参数、条件与有序效果 | 使用参数须声明；状态变化须配置效果；等待可无效果 |
| 选填；创建后定义必需 | 事件 | 名称、触发条件、有序效果、重复标记与受众 |
| 选填 | 阵营、地点、实体关系、初始记忆 | 动态关系另声明状态；私密记忆明确受众 |
| 选填的补充 | 多结局、描述性世界约束 | 更多终局需优先级；强制限制用权限、范围与条件执行 |
| 编辑器提供并可调整 | NPC 空配置、记忆窗口等运行结构 | 提供合法骨架，作者无需先填写长表单 |

这是作者填写要求，不意味着 JSON 栏目可任意省略。固定顶层结构由编辑器建立；允许空的集合和字符串采用 DSL 的当前空值，所有已声明状态必须有合法初值。平台归属与实体归属分开。

中性最小练习“夜间值班”只需要一名玩家、一项等待，以及第三回合结束的成功目标；不需要 NPC、阵营、地点、资源或事件。它用于检查通用创作能力，具体题材内容另见[示例设计](custom-scenarios.md)。

## 2. 创建、标识与模板

空白创建只初始化必要空集合和编辑器可操作的骨架，不能标记为完整定义。创建表单要求草稿名；剧本 metadata 的 name／description 可继续编辑，metadata.id 自动生成并显示为只读标识。

模板选择展示名称、说明和主要玩法，确认复制后服务端生成本人草稿，修改不会影响模板或其他副本。模板目录是创作域的只读资源，来源受控；客户端只提交 template_id，不提交服务器路径。

新增实体、动作、事件、目标和记忆时生成稳定 id；用户编辑显示名不会改变 id。字段 key 和参数名在创建时填写并按 DSL 校验，创建后只读；改变标识采用新建、替换引用、删除旧项的显式流程。导入保留合法既有标识，新建平台 draft_id 仍由服务端生成。

缺失、非法或重复的导入标识是待修复数据，不按有效标识锁死：问题区定位到本地条目，提供确认后重新生成 id，字段 key／参数名则允许修正为合法唯一值。展示所有受影响引用并要求作者逐一确认替换；重复标识无法判断引用目标时不得自动改绑。修复后标识恢复只读，整次修复可撤销。

条目复制保留文本和规则，但产生新的自身 id，保留引用的目标 id。复制状态声明时要求新的 key，并复制对应初始值；复制动作保留参数及自身条件中的参数引用，不能把其他对象重命名。

## 3. 世界、实体与角色

| 栏目 | 具体控件 | 编辑与校验行为 |
| --- | --- | --- |
| 剧本资料 | metadata.name 输入、description 多行输入、只读 id | 名称用于显示；不把草稿平台 id 写进 DSL |
| 世界 | background 多行输入、start_time 展示字符串、turn_unit 输入、constraints 文本条目增删 | 约束是描述文本；强制规则需另设条件／效果 |
| 玩家 | 角色单选，显示名称与 id | 仅可选已定义角色；不能选阵营／地点 |
| 角色 | name、description、可空 faction_id 选择；personality／goals 文本条目 | 阵营引用从实体库选择，允许无归属 |
| 阵营 | name、description、goals 文本条目 | 可添加多个；允许空列表 |
| 地点 | name、description | 可添加多个；允许空列表 |
| 关系 | 角色下的 target_id 实体选择、description；行增删 | 关系目标可选角色／阵营／地点；描述不自动创建动态状态 |
| 初始记忆 | text、多选可见角色或“公开”，只读 id | 角色私有记忆只显示给对应玩家／角色视图；作者编辑完整内容 |

引用选择器展示“名称 · 类型 · id”，支持搜索；可空引用有明确“无”选项。“公开”与具体角色名单互斥，角色名单至少一项。动作参与角色与结果受众分开编辑，不能用一个选择器同时表达两者。

编辑器中的“状态所属实体”对应 DSL owner_id，身份归属由服务端 owner_user_id 决定，界面不能把平台所有者当成世界实体。

### 3.1 NPC 详情入口

生成候选、已加入草稿以及手动新建的 NPC 使用同一套详情编辑。名称和描述只属于默认设定页；详情必须有清楚可见的“设定、性格、关系、状态、记忆、行动、行为”分组入口，不能将其余能力仅写在解释文字中。每次只展开当前分组，生成内容预填后可微调，不强制作者逐字段完成。

| 分组 | 可编辑内容 | 现有结构映射 |
| --- | --- | --- |
| 设定 | 名称、角色描述、阵营归属；稳定标识只读 | Character 与 faction_id；身份／职业写入描述，不额外增加固定字段 |
| 性格 | 性格特征、个人目标；可逐条增删 | personality、goals；个人目标文字不等同于终局条件 |
| 关系 | 目标实体与初始关系描述，可增删；动态关系链接对应局势变量 | relationships；动态信任等使用 state_schema／values |
| 状态 | 当前角色所属字段的类型、范围／候选、初值、单位与受众；新增或跳转修改关联变量 | state_schema、initial_state.values；不新增独立 NPC 数值副本 |
| 记忆 | 初始记忆／秘密，受众公开或指定角色；可增删多条 | initial_state.memories；不是单一隐含 secret 字段 |
| 行动 | 已定义行动的参与权限、参数／条件／效果和结果受众；可关联或创建行动 | actions；权限修改影响原共享行动，须显示关联影响 |
| 行为 | 是否启用、在 NPC 执行顺序中的位置、有序候选行动与具体参数；顺序调整、移除 | simulation.npc_order、npc_actions；不复制另一份优先级／触发系统 |

采纳生成候选时所有已编辑分组随同加入；后续细化不丢失手动改动。草稿里的 NPC 仍可打开这些详情；取消编辑保留原值，修改可撤销。NPC 不含尚未定义的固定血量／战斗／背包机制，这些按剧本声明字段与行动表达。人物设定的可编辑文字没有独立的可见性字段；私有信息放入带受众的记忆，不承诺隐藏 NPC 名称或公共简介。

## 4. 状态声明与初值

状态列表每行展示 label、key、类型、所属实体、可见性和初始值，详情面板根据类型显示相关控件。

属性的默认编辑入口采用一行声明式简写，下方即时显示解析摘要；类型属性表单折叠为“高级设置”。AI 生成、NPC 所属字段和独立局势变量共用这种入口。简写仅是作者输入方式，解析后仍写入当前 state_schema 与 initial_state.values，不增加引擎表达式语言，不将简写保存为第二份权威字段。

| 输入示例 | 解析含义 |
| --- | --- |
| `体力 = 8 [0..10] 点 @公开` | 整数初值 8，范围 0–10，单位点，公开 |
| `在岗 = true @私有` | 布尔初值 true，仅当前 NPC 可见；全局字段须明确选择可见角色 |
| `称号 = "维修员"` | 文本初值；省略受众时建议公开，并在摘要中明示 |
| `位置 = ref(值班室) {值班室\|灯塔} @私有` | 实体引用初值与候选；显示名须解析为明确实体 id，未知或重名要求选择，不自动创建实体 |

NPC 详情中的字段归属默认指向当前 NPC，新增 key 由编辑器生成，已有 key 不随显示名改变。未写单位使用无单位；未写可见性以公开作为明确展示的编辑器初始值。整数必须提供合法范围，不暗中补上 0–100；小数、越界和超出安全整数均报错。仅接受上述类型的字面量声明及元数据，不执行加减公式、函数、脚本或动态字段路径。

解析失败保留原始输入并定位原因，不替换此前合法字段。未解析文本只是本地编辑状态，不写入 DSL；保存／采纳前须修复或明确撤回该行编辑，不能静默丢失输入或显示已保存。合法的未完成定义仍按草稿约定保存。高级表单和表达式共享同一组已解析字段，修改任一视图后刷新另一视图，格式化本身不产生运行效果。

| 类型 | 声明控件 | 初值控件 |
| --- | --- | --- |
| integer | 必填 min／max 的安全整数输入、可空 unit | 整数输入，校验类型、范围和安全整数 |
| boolean | 不出现整数范围或实体候选 | true／false 显式选择 |
| string | 不出现整数范围或实体候选 | 文本输入，可为空字符串 |
| entity_ref | 非空 allowed_entity_ids 多选实体 | 从已选候选中单选初始实体 |

每项都可选可空 owner_id，以及公开／角色名单 visibility。新增字段时同步建立对应 initial_state.values 项；删除字段在引用检查通过后才同步删除初值。参数声明使用相同四种类型控件，但不含 owner／visibility／unit。

输入中的暂时空值属于本地未完成编辑，保存可以保留合法草稿形状；局部控件提示不能替代服务端完整定义校验。数字不得默默取整、裁剪或填成零。

改变字段类型或候选集合时先列出受影响初值、条件和效果；确认后保留其他对象里的引用并标出失配，不静默删除规则。当前项剔除不再适用的声明属性，初值要求作者显式重新选择；撤销可以恢复转换前内容。

## 5. 条件树

根节点和每个子节点可选择“全部满足 all”“任一满足 any”“取反 not”或比较。组合节点提供新增子项、复制、删除、上移／下移；not 始终恰有一个子项，不能出现多个或为空。空 all 显示“恒真”，空 any 显示“恒假”，结果文字与 DSL 语义一致。

比较节点先选 eq／ne／gt／gte／lt／lte，再编辑左右操作数。来源选择包括常量、字段、当前动作参数、候选回合；参数仅在所属动作的条件和效果内出现，候选回合仅在条件中出现。

字段选择显示类型；参数选择限定为当前动作。常量提供整数／布尔／字符串类型控件，实体等值常量用实体选择器生成 id 字符串。大小比较只提供整型来源；等值比较遵守 DSL 类型与引用规则。非法引用保留为“缺失：id”并定位，不能自动改成另一个字段。

修改节点类型先提示将替换的子结构，确认后整体替换并作为一次可撤销操作。树缩进和折叠只影响展示，不改变 all／any／not 的结构。表单控件不能产生多个来源键或混合组合／比较形状。

## 6. 效果、动作与参数

效果是有序列表，支持新增、复制、删除和上移／下移；显示序号，后项读取前项临时状态，不合并或自动重排。

| 效果 | 目标与来源控件 |
| --- | --- |
| add | 仅选择 integer 字段；value 选择整数字面量、整数字段或当前动作整数参数，允许负增量 |
| set | 选择任意声明字段；value 控件按目标类型和引用范围选择 |
| transfer | 选择不同的同单位 integer 来源／目标；amount 为非负整数来源，事件不出现动作参数 |

效果输入无 turn 选项。选择 transfer 来源后，目标列表筛选同单位字段并排除自身；任何列表筛选都不会静默改写已失效引用。预览文字可解释“从 A 转移 X 到 B”，但保存的仍是结构化节点。

动作表单包含 name／description、非空 allowed_actor_ids、参数列表、条件树、效果列表及结果 visibility。空效果明确显示“无状态效果，可用于等待”；无条件使用空 all。

参数每项含稳定参数名和四选一类型：integer 要 min／max，entity_ref 要非空候选，boolean／string 无额外约束。删除参数前展示动作条件、效果及 NPC 候选中的引用；被引用时阻止删除。无默认参数，NPC 候选和玩家动作均需显式完整填写。

## 7. 事件、目标与演化

| 项目 | 控件与行为 |
| --- | --- |
| 事件 | name、条件树、有序效果、repeatable 开关、结果受众；列表顺序就是回合扫描顺序 |
| 目标 | name、success／failure、priority 安全整数、条件树、结果受众；较小 priority 优先，同值按列表顺序 |
| NPC 顺序 | 从非玩家角色选取并显式排序，不重复；移除角色前提示候选配置及规则引用 |
| NPC 候选 | 每角色独立的有序候选列表，动作选择限定该角色有权限的动作；按参数声明生成具体参数表单 |
| 记忆窗口 | memory_recent_turns 非负安全整数；0 表示不纳入回合结果，初始记忆仍保留 |
| 叙事 | opening、style、perspective 文本；不执行文本中的脚本／模板表达式 |

NPC 顺序与 npc_actions 的键保持一致；加入角色建立空候选数组，移除角色同步去掉其候选映射。空候选显示“本回合无固定候选”，不自动生成行为。编辑候选参数或顺序后，旧试玩结果标记来源不同。

事件效果没有 parameter，目标没有 effects。仅有描述性角色 goals 不被界面解释为终局目标，目标栏目明确创建可执行的 objectives。

## 8. 引用依赖与撤销

被引用的实体、字段、参数和动作删除前，列出引用位置、对象名称及“跳转修改”。默认阻止删除；作者逐一移除或替换引用后才可删除。条件／效果引用、实体型初值、玩家角色、NPC 顺序、受众和实体候选均纳入依赖检查。删除只被本条目自有数据关联的字段时，其 initial_state.values 项随字段删除；不把该配套初值误当外部依赖永久阻止删除。条目内部从属节点随条目处理，来自其他对象的引用才须先解除。

列表重排不改变稳定 id，JSON Pointer 的数组下标会改变；本地用稳定对象 id 和节点编辑标识定位，服务端校验结果绑定那次文档快照。任一内容修改让服务端结果过期，不能把旧下标错误贴到当前条目。

一次控件确认、新增／复制／删除、树类型转换或顺序移动是一条撤销记录；普通文本连续输入在失焦时合并。撤销／重做覆盖整个本地定义和引用变化，服务端 revision 不回退。撤销后再次修改清空重做栈；重新打开另一份草稿建立新历史。保存不清空当前编辑历史。

## 9. 保存、校验与冲突

| 状态 | 展示与允许操作 |
| --- | --- |
| 已保存 | 显示最后服务端确认时间和 revision；工作副本与确认快照相同 |
| 未保存 | 明确提示；离开当前草稿时确认保存、放弃或留在页面 |
| 保存中 | 绑定提交快照和 request_id，防止重复点击；后续本地输入可继续，但不并入在途正文 |
| 保存失败 | 保留工作副本；网络重试使用原正文与 request_id，新修改等待原请求状态确定 |
| 修订冲突 | 不覆盖本地内容；展示当前服务端 revision，允许下载本地副本、重新加载或明确另存本人新草稿 |
| 身份失效 | 保留工作副本，暂停私有操作；恢复原账号后才重试，换账号不自动提交旧内容 |

若保存期间发生新修改，成功响应只确认在途快照及新 revision，保留后续本地修改并继续显示未保存。失败或 409 不清空撤销历史。读入其他草稿前若当前内容未保存，执行相同离开提示。

校验／试玩／定稿从“保存并执行”流程调用：提交并确认当前工作副本，在同一确认 revision 上操作；期间再修改则取消后续操作并提示重新保存。校验只返回问题，不保存草稿或产生世界。

错误面板区分本地表单错误、服务端结构／语义错误和过期结果，点击定位到具体属性。没有警告生成能力时不伪造警告；错误必须阻断试玩和定稿，警告不能冒充目标可达性证明。

## 10. 导入与导出

导入选择本地 JSON 文件，拟定上限 2 MiB。先解析再调用服务端，不可解析的文件指出行／列且不创建草稿。导入总是创建新草稿；已有编辑内容不被替换，导入前处理离开提示。

导入可接受当前完整／未完成 DSL 对象，或本编辑器的草稿交换封装；封装只提取 document 并重新校验，既有 valid／issues 不被信任。服务端拒绝平台 owner、认证和世界存档根字段。顶层只接受当前 DSL 栏目，未知顶层字段及非对象根拒绝。已知栏目内合法但不完整或结构错误的定义成为可修复草稿并显示问题，不能自动试玩。

缺失栏目提供“建立该栏目”；错误类型或未知子属性在定位处显示只读原值，并提供“替换为该类型骨架”或“删除未知属性”。确认前展示会丢弃的子结构，操作可撤销；未确认前保留原数据，不静默补齐或丢弃。其余有效栏目照常编辑，修复全程使用领域操作，不要求作者手写 JSON。

“导出剧本”要求服务端确认的有效修订，下载仅 ScenarioDefinition 的 scenario.json；“导出草稿”下载 {document, valid, issues} 的 .draft.json，允许无效定义并醒目标注未完成。这是作者交换封装，只有一个当前 DSL，不提供旧版本读取。

导出以已保存 expected_revision 为准；有修改时先保存。导出不包含账号、草稿平台 id／revision、定稿数据库行、登录数据或游戏状态；问题只描述定义，不能混入私有世界轨迹。

## 11. 试玩与定稿

试玩成功创建独立 preview，显示来源名称／revision、回合、状态、合法玩家动作描述、可见字段和反馈。参数表单按动作声明生成；拒绝动作不推进时间。“重新开局”使用新 request_id 创建新 preview，不重写旧会话；编辑变化不自动重置试玩。

玩家视图只能看到对应角色的信息。作者轨迹通过本人 preview 的 debug 入口显示按顺序的玩家／NPC／事件裁决、拒绝原因、字段前后值及终局；两个视图明确切换。记录可能包含私有信息，禁止用于 play 视图或一般错误提示。

定稿入口展示将采用的已保存修订、校验结果和不可修改快照说明。确认后服务端事务重新校验并创建 ScenarioRelease，重试返回同一定稿；草稿后续变化不改定稿。“开始游戏”从该 release_id 创建 play，转到游戏页面；失败保留定稿并允许原请求重试。

定稿允许重复针对同一 revision 显式创建不同请求产生不同 release，但界面阻止无意重复点击。同名对象通过来源修订和时间区分。当前不提供公开发布、定稿覆盖或删除。

## 12. 创作域服务与流程约束

创作域拥有全部 templates／drafts／releases 作者 API，包括基础 CRUD、导入导出、校验、preview 创建入口和定稿事务。身份模块提供可信上下文，创作域执行对象授权；世界域拥有创建 preview 的通用能力、行动、视图和 debug，创作域通过应用接口调用它。

草稿允许未完成，定稿和试玩必须调用引擎的统一完整结构／语义校验。定稿及创建类对象与业务请求结果同事务；草稿更新必须 owner + id + expected_revision 条件更新。创建 preview／定稿时，在短事务内锁定或等效序列化来源草稿，再确认 owner、expected_revision 和已验证快照；并发保存先完成则拒绝旧修订，创建先取得来源则保留该准确快照。不能只在事务前读一次草稿后无条件创建。HTTP 字段、错误、请求去重详见 [API 契约](api-contract.md)。

通用编辑器使用中性的空白练习检查全部控件与作者流程；具体示例通过这些标准控件从空白制作大明和空间站。已有手写／生成 JSON 或规则测试不能替代真实的编辑、保存、试玩及定稿流程。
