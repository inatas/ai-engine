# 回合交互、场景与分支流转

更新日期：2026-10-14。本文维护当前确定的目标设计，尚未在程序中实现。现有程序仍采用一个动作推进一回合，不能将本设计当作已上线能力。

职责：回合模式、场景／剧情节点、分支与交互提交语义唯一维护在本文。关联：[DSL](scenario-schema.md)、[运行机制](runtime.md)、[个人存档](personal-saves.md)、[API](api-contract.md)、[架构](architecture.md)。具体题材和对白不进入通用引擎。

## 1. 两种推进方式

同一个引擎支持以下两种推进方式，由剧本的回合节点显式指定，不从界面按钮或 AI 文案推断。

| 模式 | 交互与推进 |
| --- | --- |
| action | 每次合法动作即时结算，并自动结束当前回合、推进下一回合；保留现有玩法 |
| scene | 当前回合内允许多轮交流和动作，逐次提交真实后果；只有通过“结束回合”才完成回合结算及剧情流转 |

scene 模式中的过渡节点只提供“结束回合”按钮：显示开篇／过渡正文，没有玩家行动、输入框或对话选项。它仍是完整剧情节点，可以执行明确配置的进入／结束效果并分叉，不要求添加等待动作。无其他操作不等于自动推进，必须由玩家点击确认。

turn 不固定等于一天、一处地点或一条消息。时间跨度由剧本明确描述及规则表达。scene 模式的结束操作不能同时作为一个普通等待动作再扣一次资源或推进两次。

## 2. 分支图与回合计数

剧情 turn 是有稳定 ID 的节点，节点间由带条件的有向边连接。结束当前回合可能前往不同剧情节点，不是将固定剧情数组下标加一。节点可以跳转、汇合；允许作者明确配置的重复访问，不静态展开所有可能路径。

运行状态分别保存：

- 已完成回合计数 turn：单调增加，用于顺序历史与进度展示；初始为 0。
- 当前剧情节点 current_node_id：决定内容、模式、互动与后继边，不能以 turn 计数推导。
- 当前节点实例 node_instance_id：每次进入分配新的实例身份，区分重复访问；身份由应用层提供，engine 不调用随机源。
- 当前实例内交互序号与节点访问次数：区分本轮已提交交流、一次性互动及跨场景引用。
- 已走路径：按实例记录起点、选择的流转边和目标，不提前保存尚未发生的分支。

例如“初次审讯”可以根据承认、证据与怀疑状态通向“暂时获释”“夜间拘留”或“再次对质”。这几个后继都可能是下一回合，不能把数字回合号当作剧情身份。恢复检查点后采取不同互动，可以走不同后继边，原分支保留。

结束后仍可停留同一地点与同一组人物，进入下一段剧情；不能规定每次结束必换场景。持续的 action 玩法可使用重复进入的 action 节点，不要求作者编写无穷节点。

## 3. 场景与剧情节点定义

场景描述当前情境；剧情节点描述该情境在故事中的一次阶段。多个节点可以引用同一场景。作者无需为同一地点复制全部背景，但不同阶段的在场人物、开篇和互动必须可以明确配置。

| 定义 | 必需语义 |
| --- | --- |
| 稳定 ID、名称、场景引用 | 节点和场景独立标识，禁止依赖数组位置或显示名引用 |
| 地点与在场人物 | 引用既有实体；按明示条件决定当前参与者，不能因全局存在就允许对话 |
| 进入条件 | 初始节点及所有流转都校验，不能仅靠来源边绕过 |
| 推进模式 | action 或 scene；scene 可为互动或仅结束按钮的过渡节点 |
| 开篇 | 配置正文或 AI 生成配置与静态后备正文，见第 5 节 |
| 可用互动 | 引用允许的动作、对话对象／话题与条件；受角色权限及信息范围约束 |
| 进入效果 | 可空；进入实例时仅执行一次，合法效果原子提交 |
| 结束条件与结束效果 | scene 的结束按钮须有明确合法条件；过渡节点可无条件结束。结束效果可空 |
| 后继边 | 稳定 ID、目标节点、条件与明确优先级；以结束结算后的状态评估 |

匹配后继边时，同时校验边条件和目标进入条件；优先级从小到大，相同优先级按定义顺序，作者可查看实际优先关系。需要玩家选路时应配置场景内的选择互动，写入状态供后继边求值；AI 不直接指定任意目标节点。

非终局节点须有可表达的后继或明确默认边。运行时没有合法后继则拒绝整个结束操作，保留当前回合及已提交的场景内进度，不能静默选择首项、自动编造场景或假装通关。静态校验检查引用及过渡节点约束；实际分支可达性与死路还须试玩验证。

## 4. 场景内事实与结束结算

交流和行动不是直到结束才生效的临时表单。每次成功提交都更新实时属性、数值、角色判断、已发生记忆和交互记录，增加 session revision，scene 模式下不增加 turn 计数。后续互动必须看到这些事实；已经交出的部件不能继续作为持有物使用。

纯表达的对话也保存已完成消息及知识范围，但不凭文本隐式扣费、增加信任或生成证据。若交流构成承认、承诺、指控等事实变化，须映射到剧本允许且引擎验证的明确效果。无效提议不修改事实或推进回合，不作为已执行行动保存。

引擎调度区分 interaction（场景内已提交互动）和 turn_end（结束回合）。NPC 反应及事件须明确所属时机；同一交互或结束提交内，每名配置 NPC 和每个匹配事件最多按既定顺序处理一次，不递归无限扫描。过渡节点不隐含运行全体 NPC 或资源消耗；其调度由剧本明确配置。

scene 的结束操作依次：校验结束条件 → 执行结束阶段配置的 NPC／事件及节点结束效果 → 检查终局 → 非终局选择合法后继并执行其进入效果 → 提交完整候选状态。任何阻断错误不部分提交；此前场景内成功互动不被回滚。具体阶段的顺序必须在共享执行契约落地前固定，不能由某个示例另行实现。

action 的动作及结束流转属于同一个原子提交，动作成功但流转失败不能留下半个回合。两种模式共享事实、权限、规则校验和记录体系。

终局条件也在每次互动结算后检查，避免角色死亡、关键目标完成后仍能继续无效交流。若互动已直接达成终局，关闭当前实例并记入一个完成回合，不再要求玩家点击结束，不执行下一节点或重复结束阶段调度。非终局时仍由推进模式决定是否自动结束。

## 5. 每个回合的开篇

每次进入剧情节点实例都必须提供足够的开篇，交代当前可知的地点、在场人物、局势、上轮可见后果和当前行动情境，不能只显示回合号或资源数值。

- 配置正文：使用剧本内的对应节点文本，不能只有整局唯一 opening。
- AI 开篇：应用层根据节点写作规则、当前状态和玩家可知历史生成；不能改写既定事实、泄露私有信息或产生可执行效果。必须配置可用的静态后备正文。

进入状态先按规则提交；模型调用在事务外进行。生成结果绑定会话、节点实例及依据 revision，来源已变化的结果不得覆盖当前正文。正文属于持久化展示产物，记录其来源、依据和受众；重读与读档显示已完成版本，不重新随机生成。生成失败使用该节点后备正文，单独重试叙述不能再执行进入效果或推进回合。

自由对话遵循相同模型边界：角色只使用其获准知识回应；模型解释意图或生成表达，引擎决定合法效果。完整角色秘密不能发给只负责玩家开篇的模型上下文。

## 6. 保存与恢复要求

每次完成交流、动作、结束或叙事产物提交，都自动持久化完整当前状态；用户随时手动存档复制最新服务端已提交快照，不能只允许回合结束后保存。

完整载荷包含当前 turn、剧情节点与实例、实时属性数值、已完成交流及行动记录、正文、节点访问／进入效果标记、已发生的事件与 memory、角色知识、内部裁决和已走路径。玩家不可见内容同样保存，由服务端视图过滤，不能以“不显示”为理由丢弃。

进行中的模型请求与尚未确认的输入不算已完成交流；保存不能等待未知模型结果或伪装其已执行。恢复后读取已提交进度，允许重新提交未完成输入，禁止重做已生效互动、进入效果或结束结算。

格式、版本、门禁、并发和恢复唯一规范见[个人存档](personal-saves.md)。这次变更要求递增 schemaVersion，只读取新版本，不迁移旧会话或旧检查点。

## 7. 实施前必须落实的契约

以上是确定的行为要求。正式编码前还须落实严格 Zod 字段形状、阶段调度顺序、模型输入／输出及叙述过滤、HTTP DTO 与幂等范围、保存历史一致性校验和编辑器控件。不能把任意脚本、未校验模型输出或 Ink 运行时作为捷径带入 engine。

必需验证：action 一次动作只推进一次；scene 多次互动即时保存但不推进；结束按钮按条件选分支；过渡节点只有结束操作；不同互动到达不同后继；重复访问效果仅按实例执行；同场景下一剧情；开篇失败后备与迟到响应；私有交流／记忆过滤；场景中途重登和读档恢复；并发／丢失响应重试不重复效果；无合法后继拒绝结束；终局后禁止互动；当前版本完整性与旧版明确拒绝。
