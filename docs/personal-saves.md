# 世界持久化与个人存档

关联：[001](../note/001-world-engine-foundation.md)、[运行机制](runtime.md)、[身份与访问](auth-and-ownership.md)、[API](api-contract.md)。本文件唯一维护完整世界检查点、版本、自动提交及保存恢复；身份凭据和回合计算分别由对应规范维护。

## 1. 持久化对象与检查点

WorldSession 保存当前世界；SaveGame 保存不可修改的具名检查点。二者属于世界域，各自含平台 owner、对象标识、版本和列表概要列，完整世界内容存于 JSONB。

当前完整载荷必须覆盖 schemaVersion、scenario_snapshot、剧本身份、turn／status、values、known_records、fired_events、terminal_objective_id 和完整 turns。每条历史保留来源 session_id／request_id、玩家输入及裁决／变化／受众，恢复不重放历史。

当前 schemaVersion 初始 1，由服务端生成；列与载荷根必须同事务一致。会话 id、owner、mode、revision 是应用元数据，不属于作者 DSL。known_records 是角色可知记录引用，可用初始记忆及回合事实核对，不能变成另外一份可任意修改的权威状态。

ProcessedRequest 是应用层事务账本，不把响应缓存同时写进核心世界 JSON 作为第二个权威来源；业务范围按 API 契约。检查点不携带可在新分支复用的账本，恢复后新 session_id 对应空账本。历史中的旧来源仍保留。

现有纯计算 World 和基础表不足以满足此完整载荷要求。001 必须补齐持久化结构、引用与历史一致性验证后才提供读取／恢复。

## 2. 版本与完整性门禁

顺序固定：认证 → 对象归属 → 版本 → 完整载荷 → 业务去重／模式／revision。世界继续、行动、debug、保存、详情与恢复都执行；去重命中也不能绕过门禁。

| 情形 | 结果 |
| --- | --- |
| 列或载荷版本缺失、非法 | 422 checkpoint_version_unsupported |
| 两侧版本合法但不一致 | 500 checkpoint_invalid |
| 两侧版本一致但非当前版本 | 422 checkpoint_version_unsupported |
| 当前版本结构、状态、引用或历史损坏 | 500 checkpoint_invalid |
| 他人对象 | 在版本及载荷检查前返回 404 object_unavailable |

完整校验至少覆盖 DSL、全部状态值的类型／范围、事件及终局引用、角色知识引用、历史回合顺序和已提交回合一致性。错误不返回私有内容，不推进世界、不部分写入或创建恢复分支。

列表只读取本人独立概要列，含 schemaVersion 和 loadable；loadable 仅表明版本受支持，不保证载荷完整。详情仍重新校验。不可用存档显示“此存档已无法使用，请开始新游戏”，损坏显示读取失败，不能自动新建世界掩盖失败。

存档结构或恢复语义的破坏性变化递增版本，包括无法按当前规则解释的内嵌 DSL／历史语义变化。内容文案或另一个剧本不自动递增。只支持当前版本，直接重新生成数据，不补默认字段或迁移。

## 3. 自动提交

合法回合先计算候选状态，再在短事务内以 owner、session_id、expected_revision 条件提交：值、回合、知识、事件标记、终局、TurnRecord、概要及请求结果一起生效，revision 增加 1。

同 revision 的行动竞争只允许一个提交。持久化失败保留最后已提交世界，失败请求没有成功账本，可用原输入重试。网络丢失响应后按 API 的相同请求返回已提交结果，不重复执行引擎。

恢复或读取的世界也经过完整校验。第一期世界历史量小，完整 JSONB 事务保存即可；不引入事件重放存储或独立记忆数据库。

## 4. 手动保存与列表

保存从本人已提交 play 会话复制检查点，按 expected_revision 检查，不接收客户端权威状态。preview 不允许正式保存。名称只作展示，允许同名，每次新请求产生独立 save_id，原检查点不可覆盖；本期不提供删除／改名。

保存不增加世界 revision。保存与行动竞争必须在事务内对同一来源序列化检查：保存先取得有效来源可以成功，之后行动仍可提交；若行动已推进，旧 revision 保存冲突。锁定／等效事务控制必须由实际 PostgreSQL 并发验证，不能先读快照再无条件插入。

列表区分当前世界和手动检查点，按本人过滤，返回名称、剧本名称、回合、状态、时间及版本概要。SaveView 仅含保存时玩家可见内容，不暴露完整快照、NPC 私有记忆或内部轨迹。

## 5. 恢复与继续

“继续游戏”读取当前 WorldSession；“恢复检查点”复制 SaveGame 为新的 play 会话。后者赋新 session_id、revision=0、空去重账本，保持保存时定义、回合、值、知识、事件标记、历史和终局。

恢复不修改原世界／检查点，不重播事件，不采用当前草稿或最新定稿，终局仍为终局。恢复创建与请求结果同事务，重复请求只返回同一个新会话。玩家视图在新分支标识下重新产生，历史来源不被改写。

## 6. 必需证据

使用两个真实账号直接调用世界与存档入口；验证越权、版本缺失／旧／未来／损坏、并发行动／保存、重复请求、事务故障、退出重登及重启恢复。完整检查点一致性不能只靠结构 schema 或通用数据库探针证明。验收编号和实际结果由 001 维护。
